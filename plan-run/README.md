# plan-run

**승인받은 계획서를 작업 단위로 실행합니다.**

> "계획대로 해줘", "이 계획 실행해줘"

[`design-first`](../design-first/) 의 architectural 갈래가 계획서를 만들고 여기로 넘어옵니다.
계획서가 없으면 이 skill 이 아닙니다.

## 전제

**대화 기억은 컨텍스트가 압축되면 사라집니다.** 작업이 열 개쯤 되면 도중에 자기 위치를 잃습니다.
그래서 진행을 `.claude/plan-progress.md` 에 적습니다. 세션이 끊겨도 그 파일부터 읽고 이어갑니다.

**작업마다 새 팀원을 띄웁니다.** 팀장이 직접 구현하면 작업 열 개의 코드가 전부 팀장 컨텍스트에
쌓입니다. 팀원은 자기 작업만 알고 팀장에게는 정리된 결과만 올립니다.

**구현이 끝났다고 동작하는 것은 아닙니다.** 마지막에 [`verify-impl`](../verify-impl/) 로 넘깁니다.

## 흐름

```
동시 세션 확인
  -> 이전 진행 확인 · 재개      (.claude/plan-progress.md)
  -> 계획 읽기 · 작업 쪼개기    (완료 조건이 관측 가능한가)
  -> 작업 순서 · 위험 확인      (블로킹. 되돌리기 어려운 것을 미리 짚음)
  -> 작업 루프
       plan-implementer  -> plan-reviewer -> 커밋 -> 진행 갱신
  -> 마무리 보고                (한 작업도 빠짐없이 상태를 적음)
  -> verify-impl 로 넘김
```

## 팀

| 팀원 | 담당 | 왜 분리하나 |
|------|------|-------------|
| `plan-implementer` | 작업 하나 구현 | 작업 열 개의 코드가 팀장에 안 쌓인다 |
| `plan-reviewer` | 계획 대조 | 만든 사람이 자기 것을 보면 안 보인다 |

`plan-reviewer` 는 **계획 준수**만 봅니다. 코드 품질은 `/code-review` 자리입니다.

## 완료 조건

작업마다 **관측 가능한** 완료 조건이 있어야 합니다. 없으면 시작하지 않고 묻습니다.

| 나쁜 조건 | 좋은 조건 |
|-----------|-----------|
| 알림이 잘 간다 | 임계치 초과 1건 후 목 서버에 POST 1건이 들어온다 |
| 설정이 반영된다 | 잘못된 값으로 기동하면 exit 1 이 난다 |

계획서 틀은 `templates/plan.md` 에 있습니다.

## 검토가 걸릴 때

| 라운드 | 행동 |
|--------|------|
| 1~2 | 같은 팀원이 고칩니다 |
| 3 | 새 팀원을 띄웁니다 |
| 4 | 멈추고 사람에게 넘깁니다. 계획이 틀렸을 수 있습니다 |

상한 없이 반복하지 않습니다.
