# hooks

시크릿 유출과 잘못된 커밋 메시지를 **커밋 시점에** 막습니다.

문서에만 적힌 규칙은 세션이 바뀌면 새기 때문에, 막을 수 있는 것은 훅으로 막습니다.

## 설치

```sh
~/.claude/skills/hooks/install-hooks.sh <repo>            # 프로필 자동 결정
~/.claude/skills/hooks/install-hooks.sh <repo> private    # 명시 지정
```

`pre-commit` 과 `commit-msg` 가 함께 설치됩니다.
기존 훅이 있으면 `<훅이름>.orig` 로 옮겨 체인하므로 husky 같은 것이 안 깨집니다.
같은 repo 에 다시 돌려도 안전합니다.

기본은 심볼릭 링크입니다. **링크를 못 만드는 환경(개발자 모드가 꺼진 Windows)에서는 복사**합니다.
복사여도 훅은 그대로 동작하지만, 이 repo 를 `git pull` 한 뒤에는 다시 돌려야 갱신됩니다.

해제는 `.git/hooks/` 에서 `pre-commit`, `commit-msg`, `.profile` 을 지우면 됩니다.

```sh
rm .git/hooks/pre-commit .git/hooks/commit-msg .git/hooks/.profile
```

**원래 훅이 있던 repo 라면 한 줄이 더 필요합니다.** 설치할 때 `<훅이름>.orig` 로 옮겨 뒀기 때문에,
위 세 개만 지우면 원래 훅이 되살아나지 않고 `.orig` 인 채로 남습니다.

```sh
mv .git/hooks/pre-commit.orig .git/hooks/pre-commit    # .orig 가 있을 때만
mv .git/hooks/commit-msg.orig .git/hooks/commit-msg
```

설치 스크립트도 끝에 이 명령을 같이 냅니다. `.orig` 가 실제로 있을 때만 나옵니다.

## 프로필

공개 repo 와 사내 repo 는 막아야 할 것이 다릅니다.
사내 repo 에서는 내부 조직명과 사설 IP 가 정상적인 내용이기 때문입니다.

| 프로필 | 추가로 막는 것 |
|--------|----------------|
| `private` | 없음 (시크릿만) |
| `public` | 내부 조직명, 사설/공인 IP |

프로필은 **설치 시점에 `gh` 로 공개 여부를 확인해** 정하고 `.git/hooks/.profile` 에 적어 둡니다.
훅에서 매번 확인하면 느리고, 비공개 repo 를 공개로 오판해 정상 커밋을 막게 됩니다.
확인이 안 되면 오탐이 적은 `private` 로 갑니다.

## 무엇을 막나

### pre-commit

스테이지된 내용만 봅니다.

| 검사 | 프로필 |
|------|--------|
| 비밀번호로 보이는 문자열, JWT, GitHub 토큰, AWS 키, 개인키 | 항상 |
| 사내 이름(조직·제품), 문서용이 아닌 IP | `public` 만 |
| em dash | 항상 |
| `.claude/verify-targets.md` 등 접속 대상 파일 | 항상 |

IP 는 문서용 대역만 통과합니다. `10.0.x.x` 와 TEST-NET(`192.0.2.x`, `198.51.100.x`, `203.0.113.x`) 입니다.
**`192.168.x` 와 `172.16~31.x` 는 사설 대역이지만 막습니다.** 사내망 주소가 그대로 들어가는 일이 많아서입니다
(`hooks/pre-commit` 의 허용 목록이 정본입니다).

### 사내 이름 목록은 소스에 두지 않습니다

막으려는 이름을 막는 코드 안에 적어 두면, 훅이 공개 repo 에 올라가는 순간 그 이름이 같이 나갑니다.
그래서 목록은 **커밋되지 않는 곳**에서 읽습니다. 먼저 찾은 것부터 전부 합칩니다.

| 순위 | 위치 | 쓰임 |
|------|------|------|
| 1 | `HOOK_ORG_PATTERNS` (파일 경로) | 테스트·CI |
| 2 | `<repo>/.git/hooks/.org-patterns` | 그 repo 에만 추가할 이름 |
| 3 | `~/.claude/hook-org-patterns` | 전 repo 공통 |

한 줄에 정규식 하나, `#` 로 시작하는 줄과 빈 줄은 무시합니다.

```
innogroup
example-corp
admin@example.com
# 부분 문자열 오탐을 막으려면 직접 경계를 줍니다.
# 공개 모듈 경로가 사내 제품명에 걸리던 문제라 앞에 하이픈이 붙으면 넘깁니다.
(^|[^-])app-manager
```

**목록이 없으면 그 검사만 건너뛰고 한 줄로 알립니다.** 조용히 지나가지 않습니다 - 검사가 실행되지 않는 것을
통과로 읽는 게 이 repo 가 가장 경계하는 실패입니다. 시크릿·IP·em dash 검사는 목록과 무관하게 그대로 동작합니다.

### commit-msg

| 검사 | 왜 |
|------|-----|
| `Co-Authored-By` | 쓰지 않기로 했습니다 |
| AI 생성 문구 | 마찬가지입니다 |
| em dash | 표기 규칙입니다 |
| 제목 뒤 ` - ` 부연 | 부연은 제목이 아니라 본문에 씁니다 |
| 제목과 본문 사이 빈 줄 | 없으면 git 이 둘째 줄까지 제목으로 봅니다 |

**본문 자체는 막지 않습니다.** 부연이 필요하면 제목 다음 빈 줄 뒤에 쓰면 됩니다.

`Revert "..."`, `Merge ...`, `fixup!` 로 시작하는 제목은 제목 규칙에서 뺍니다.
남의 커밋 제목을 그대로 인용하는 것이라, 거기 들어 있는 ` - ` 는 내가 붙인 부연이 아닙니다.

## em dash 와 커밋 메시지는 프로필을 안 가립니다

시크릿이 아니라 표기 규칙이기 때문입니다. 공개든 비공개든 같은 규칙으로 씁니다.

## 우회

정말 필요할 때만 씁니다.

```sh
git commit --no-verify
```

훅이 막는 것은 커밋뿐입니다. **PR 본문은 못 막습니다.**
공개 upstream 에 올릴 때는 본문에 내부 정보가 없는지 사람이 따로 봐야 합니다.
