# hooks

시크릿 유출과 잘못된 커밋 메시지를 **커밋 시점에** 막습니다.

문서에만 적힌 규칙은 세션이 바뀌면 새기 때문에, 막을 수 있는 것은 훅으로 막습니다.

## 설치

```sh
~/.claude/skills/hooks/install-hooks.sh <repo>            # 프로필 자동 결정
~/.claude/skills/hooks/install-hooks.sh <repo> private    # 명시 지정
```

`pre-commit` 과 `commit-msg` 가 함께 설치됩니다.
기존 훅이 있으면 `<훅이름>.orig` 로 옮겨 체인하므로 husky 같은 것이 안 깨집니다.
같은 repo 에 다시 돌려도 안전합니다.

기본은 심볼릭 링크입니다. **링크를 못 만드는 환경(개발자 모드가 꺼진 Windows)에서는 복사**합니다.
복사여도 훅은 그대로 동작하지만, 이 repo 를 `git pull` 한 뒤에는 다시 돌려야 갱신됩니다.

해제는 같은 스크립트로 합니다.

```sh
~/.claude/skills/hooks/install-hooks.sh <repo> --uninstall
```

**손으로 `rm` 하지 마세요.** 그 파일이 내가 놓은 것인지 원래 있던 것인지를 사람이 매번 가릴 수 없습니다.
해제 모드는 지우기 전에 표식(`jolla-skills-hook` / `jolla-skills-chain`)을 보고 판단합니다.

| 그 repo 의 상태 | 해제하면 |
|-----------------|----------|
| 내가 놓은 훅만 있음 | 지웁니다. |
| 원래 훅이 있어서 체인해 둠 | 체인을 지우고 `<훅이름>.orig` 를 원래 자리로 되살립니다. |
| **표식이 없는 훅** (내가 놓은 게 아님) | **그대로 둡니다.** 지웠다고 말하지 않습니다. |
| `.profile` | 지웁니다 (설치할 때 만든 파일) |
| `.org-patterns` | **그대로 둡니다** (직접 쓰신 목록) |

## 프로필

공개 repo 와 사내 repo 는 막아야 할 것이 다릅니다.
사내 repo 에서는 내부 조직명과 사설 IP 가 정상적인 내용이기 때문입니다.

| 프로필 | 추가로 막는 것 |
|--------|----------------|
| `private` | 없음 (시크릿만) |
| `public` | 내부 조직명, 사설/공인 IP |

프로필은 **설치 시점에 `gh` 로 공개 여부를 확인해** 정하고 `.git/hooks/.profile` 에 적어 둡니다.
훅에서 매번 확인하면 느리고, 비공개 repo 를 공개로 오판해 정상 커밋을 막게 됩니다.
확인이 안 되면 오탐이 적은 `private` 로 갑니다.

## 무엇을 막나

### pre-commit

스테이지된 내용만 봅니다.

| 검사 | 프로필 |
|------|--------|
| 비밀번호로 보이는 문자열, JWT, GitHub 토큰, AWS 키, 개인키 | 항상 |
| 사내 이름(조직·제품), 문서용이 아닌 IP | `public` 만 |
| em dash | 항상 |
| 홈 경로·repo 절대경로가 박힌 줄 | 항상 |
| `.claude/verify-targets.md` 등 접속 대상 파일 | 항상 |
| 셸 스크립트의 shellcheck `error` | 항상 (shellcheck 이 깔려 있을 때만) |

shellcheck 이 없는 환경에서는 그 검사만 조용히 건너뜁니다. `warning` 까지 보려면
`shared/scripts/lint-shell.sh` 를 직접 돌립니다.

**막지 않고 알리기만 하는 것이 하나 있습니다.** `CLAUDE.md` 나 `SKILL.md` 가 스테이지되면
회귀를 돌려볼 명령을 한 줄 띄우고 커밋은 그대로 진행합니다. 검증은 세션을 실제로 띄우므로
시간과 토큰이 들어서, 돌릴지는 사람이 정합니다. `verify-impl/evals/run.sh` 가 있는
repo 에서만 뜨고, 돌릴 케이스 목록은 `verify-impl/evals/quick.txt` 에서 고칩니다.

```
[알림] 규칙 파일을 고쳤습니다:
         verify-impl/SKILL.md
       verify-impl/evals/run.sh E1 E2 E4 E13 E15 E27 E38
       돌릴지는 직접 정하세요. 커밋은 그대로 됩니다.
```

절대경로는 `$HOME` 과 `git rev-parse --show-toplevel` 을 실행할 때 읽어서 씁니다. 사람마다 다른 값이라
훅 안에 적어두면 그 값이 공개 repo 에 그대로 나갑니다. 조직명 목록을 커밋 안 되는 곳에서 읽는 것과 같은 이유입니다.
문서에서 쓰는 `~/.claude/...` 같은 물결표 표기와 `$(dirname "$0")` 은 걸리지 않습니다.

IP 는 문서용 대역만 통과합니다. `10.0.x.x` 와 TEST-NET(`192.0.2.x`, `198.51.100.x`, `203.0.113.x`) 입니다.
**`192.168.x` 와 `172.16~31.x` 는 사설 대역이지만 막습니다.** 사내망 주소가 그대로 들어가는 일이 많아서입니다.
(`hooks/pre-commit` 의 허용 목록이 정본입니다).

### 사내 이름 목록은 소스에 두지 않습니다

막으려는 이름을 막는 코드 안에 적어 두면, 훅이 공개 repo 에 올라가는 순간 그 이름이 같이 나갑니다.
그래서 목록은 **커밋되지 않는 곳**에서 읽습니다. 먼저 찾은 것부터 전부 합칩니다.

| 순위 | 위치 | 쓰임 |
|------|------|------|
| 1 | `HOOK_ORG_PATTERNS` (파일 경로) | 테스트·CI |
| 2 | `<repo>/.git/hooks/.org-patterns` | 그 repo 에만 추가할 이름 |
| 3 | `~/.claude/hook-org-patterns` | 전 repo 공통 |

한 줄에 정규식 하나, `#` 로 시작하는 줄과 빈 줄은 무시합니다.

```
innogroup
example-corp
admin@example.com
# 부분 문자열 오탐을 막으려면 직접 경계를 줍니다.
# 공개 모듈 경로가 사내 제품명에 걸리던 문제라 앞에 하이픈이 붙으면 넘깁니다.
(^|[^-])app-manager
```

**목록이 없으면 그 검사만 건너뛰고 한 줄로 알립니다.** 조용히 지나가지 않습니다 - 검사가 실행되지 않는 것을
통과로 읽는 게 이 repo 가 가장 경계하는 실패입니다. 시크릿·IP·em dash 검사는 목록과 무관하게 그대로 동작합니다.

### commit-msg

| 검사 | 왜 |
|------|-----|
| `Co-Authored-By` | 쓰지 않기로 했습니다. |
| AI 생성 문구 | 마찬가지입니다. |
| em dash | 표기 규칙입니다. |
| 제목 뒤 ` - ` 부연 | 부연은 제목이 아니라 본문에 씁니다. |
| 제목과 본문 사이 빈 줄 | 없으면 git 이 둘째 줄까지 제목으로 봅니다. |
| 접두사가 통째로 빠진 제목 | 접두사가 빠진 커밋이 들어가면 히스토리를 다시 쌓아야 합니다. |
| 그 repo 의 티켓번호 | 티켓을 다는 repo 에서 빠지면 나중에 무엇 때문에 한 커밋인지 못 찾습니다. |

**본문 자체는 막지 않습니다.** 부연이 필요하면 제목 다음 빈 줄 뒤에 쓰면 됩니다.

`Revert "..."`, `Merge ...`, `fixup!` 로 시작하는 제목은 제목 규칙에서 뺍니다.
남의 커밋 제목을 그대로 인용하는 것이라, 거기 들어 있는 ` - ` 는 내가 붙인 부연이 아닙니다.
접두사·티켓 검사도 같은 이유로 건너뜁니다.

### 접두사와 티켓은 그 repo 의 프로필을 보고 겁니다

접두사 체계는 repo 마다 다릅니다. `fix:`/`feat:` 를 쓰는 곳, `모듈명:` 을 쓰는 곳,
접두사를 안 쓰고 티켓만 다는 곳이 다 있습니다. 그래서 무엇을 요구할지를 훅에 적어 두지 않고
**`<repo>/.claude/repo-profile.md` 를 읽어서** 정합니다. `shared/scripts/repo-profile.sh` 가 만드는 파일입니다.

| 프로필 상태 | 훅 동작 |
|-------------|---------|
| 파일이 없음 | 검사하지 않습니다 |
| 접두사 판정이 `conventional` | 제목에 접두사가 아예 없으면 막습니다 |
| 티켓번호가 분석 대상의 과반 | 제목에 티켓번호가 없으면 막습니다 |
| 접두사 판정이 `스코프형` / `접두사 없음` | 접두사는 검사하지 않습니다 |
| 어느 행이든 읽지 못함 | 그 검사만 건너뜁니다 |

접두사와 티켓은 따로 겁니다. 둘 다 걸리는 repo 도, 하나만 걸리는 repo 도 있습니다.

티켓 과반의 분모는 `- 분석 범위:` 줄의 `최근 N 개` 입니다. 그 줄이 없으면 과반을 계산할 수 없어 검사하지 않습니다.

**`스코프형` 은 검사하지 않습니다.** 모듈명이 자유 문자열이라 무엇이 접두사이고 무엇이 그냥 제목인지
훅이 가릴 수 없습니다. 오탐으로 멀쩡한 커밋을 막느니 안 겁니다.

### 접두사는 형태만 보고 낱말은 안 봅니다

`conventional` 로 뽑힌 repo 에서 보는 것은 **접두사가 있는지와 그 형태**입니다. 어느 낱말인지는 안 봅니다.

| 제목 | 결과 |
|------|------|
| `feat: 무엇을 했다` | 통과 |
| `docs(scope): 무엇을 했다` | 통과 (스코프는 선택) |
| `chore!: 무엇을 했다` | 통과 (`!` 는 파괴적 변경 표시) |
| `build: 무엇을 했다` | 통과 (프로필에 자주 안 나오는 접두사여도 됩니다) |
| `그냥 제목` | 막힘 (접두사가 없습니다) |
| `Feat: 무엇을 했다` | 막힘 (접두사는 소문자로 씁니다) |
| `feat:붙여씀` | 막힘 (콜론 뒤에 공백이 있어야 합니다) |

**낱말 목록으로 거르지 않습니다.** 처음에는 프로필의 `### 접두사 top 10` 을 허용 목록으로 썼는데
그게 틀렸습니다. 그 블록은 **빈도 상위 10칸을 자른 목록**이지 허용 목록이 아닙니다.

- 스코프를 붙인 변형들(`fix(a):`, `fix(b):`)이 10칸을 다 채우면 `docs:` 나 `build:` 가 목록 밖으로 밀립니다.
  같은 프로필의 `### 최근 제목 10개` 에 실려 있는 제목을 훅이 막는 일까지 났습니다.
- 프로필은 **뽑은 날의 기록**입니다. 그 뒤에 새로 쓰기 시작한 접두사는 목록에 없습니다.

잡으려는 것은 접두사가 통째로 빠진 제목이지 낱말 선택이 아닙니다.

### 이 검사가 못 잡는 것

| 놓치는 것 | 왜 그냥 두나 |
|-----------|--------------|
| 오타 난 접두사 (`feet:`) | 형태만 보므로 통과합니다. 낱말을 고정하면 멀쩡한 커밋을 막게 됩니다 |
| 티켓이 아닌 대문자-숫자 (`UTF-8`, `RFC-2119`) | 티켓으로 인정해 통과시킵니다. 놓치는 쪽이라 커밋을 막지는 않습니다 |

둘 다 **덜 막는 쪽으로 틀립니다.** 훅이 막는 것은 되돌리기 쉽지만, 정상 커밋을 막으면 작업이 멈춥니다.

접두사 판정은 값 칸의 **집계 괄호 앞부분**만 봅니다. 값 칸에는 `conventional` 이 판정과 집계 양쪽에 나옵니다.

```
| 접두사 | **접두사 없음** (conventional 11 · 스코프형 1 · 없음 187) |
```

이 줄에서 `conventional` 이라는 낱말만 찾으면 접두사를 안 쓰는 repo 를 conventional 로 오판해
정상 커밋을 전부 막게 됩니다.

## em dash 와 커밋 메시지는 프로필을 안 가립니다

시크릿이 아니라 표기 규칙이기 때문입니다. 공개든 비공개든 같은 규칙으로 씁니다.

## 우회

정말 필요할 때만 씁니다.

```sh
git commit --no-verify
```

훅이 막는 것은 커밋뿐입니다. **PR 본문은 못 막습니다.**
공개 upstream 에 올릴 때는 본문에 내부 정보가 없는지 사람이 따로 봐야 합니다.
