# 보고 - 읽는 사람이 다시 묻지 않게

대화 응답과 **내가 쓰는 모든 문서**에 같이 적용한다. README, 설계 문서, 보고서, 커밋 본문,
이슈 답변, 릴리즈 노트가 전부 해당한다.

"변경점만 준다" 는 이미 규칙이다. 그런데도 6주치 세션에서 **17번** 다시 설명해 달라는 말이 나왔다.
짧게 쓰는 것으로는 안 잡히는 실패가 따로 있다.

## 1. 여러 곳에 작업하고 "어디에 무엇을" 이 안 보임

> "**어디에 뭘 푸시했다는거야?**"
> "인프라 repo 에 ... 업데이트 해서 커밋하라고 **말귀를 못알아 먹어**"

repo 두 개, 호스트 세 대, 브랜치 두 개를 오가는 작업이 기본이다.
서술형으로 쓰면 어디가 어디인지 사라진다. **대상이 둘 이상이면 표로 낸다.**

```markdown
| 대상 | 무엇을 | 결과 |
|------|--------|------|
| `app-manager` master | 캐시 TTL 30초 | `a1b2c3d` 커밋·푸시 |
| `terraform/infra` | asset 경로 갱신 | `e4f5g6h` 커밋, 푸시 안 함 |
| 10.0.0.11 | 재배포 | 이미지 `v1.9.6`, healthy |
| 10.0.1.11 | - | **안 했음** (지시 밖) |
```

**안 한 것도 줄에 남긴다.** 빠진 것을 사람이 찾아내게 하지 않는다.

## 2. 선택지를 냈는데 무엇을 고르라는 건지 모름

> "그래서 지금 뭘 해야 된다는거야 말아야 된다는거야 **3개가 뭔데**"
> "잠깐만 **선택지 다시 보여줘 뭐라고 했냐**"

선택지는 **설명 뒤에 묻히면 없는 것과 같다.** 규칙:

- 선택지는 **응답 맨 끝**에 둔다. 중간에 두지 않는다.
- 번호를 붙이고, 한 줄로 **차이만** 쓴다. 근거는 위 본문에 이미 있다.
- **3개를 넘기지 않는다.** 넘으면 내가 아직 정리를 못 한 것이다.
- 추천이 있으면 먼저 말한다. "고르세요" 만 던지지 않는다.

```markdown
1. TTL 30초 + warm-up  (권장 - 첫 조회 지연이 사라진다)
2. TTL 30초만          (구현 5줄, 첫 조회는 그대로 느리다)
```

## 3. 긴 분석이 안 읽힘

> "**잘 눈에 안들어 오는데** 다시 읽어보고 핵심을 말해주고 진짜 핵심적으로 뭘 하면 되는지를 말해봐"
> "야 좀 **알아 들을수 있게 쉽게** 풀어써줘"

분석이 길어질수록 **맨 앞 세 줄**이 전부다. 그 자리에 넣을 것:

1. 무엇이 사실로 확정됐는가 (한 줄)
2. 그래서 무엇을 하면 되는가 (한 줄)
3. 내가 확인 못 한 것은 무엇인가 (한 줄)

용어는 그 자리에서 푼다. **"골든", "무디스크 실행", "저주기 수집 계열", "삼켜진"** 같은 말이
그대로 나가서 되물음을 받은 전례가 있다. 내가 만든 축약어는 처음 쓸 때 한 번 풀어 쓴다.

## 4. 뜻은 맞는데 안 읽힌다

같은 지적이 6주 동안 6번 나왔다. 짧고 정확해도 **읽히지 않으면 다시 설명해야 한다.**

> "별도 저주기 수집 계열 이것도 뭔말이야 **알아들을수 있는 말로 바꿔**"
> "야 좀 **알아 들을수 있게 쉽게** 풀어써줘"
> "README 에 **기계적이란 말을 바꿨으면 좋겠는데 무슨말인지 말이안돼**"
> "결과는 **흐름도처럼 읽히게** 정리하되 장황하지 않게"

네 번 다 같은 종류다. 문법이 틀린 것도, 말투가 딱딱한 것도 아니고
**읽는 사람이 그 말을 처음 본다**는 것이다.

| 걸리는 것 | 실제로 나왔던 말 | 어떻게 |
|---|---|---|
| 그 자리에서 내가 만든 말 | `저주기 수집 계열`, `무디스크 실행` | 무엇이 무엇을 하는지 동사로 - `5분마다 따로 모으는 것`, `디스크에 안 쓰고 메모리에서 실행되는 것` |
| 설명 없이 던진 업계·도구 용어 | `골든`, `아티팩트` | 처음 쓸 때 한 번 풀고, 그다음부터 줄여 쓴다 |
| 비유 | `삼켜진`, `축` | 비유를 빼고 실제로 무슨 일이 있었는지 - `.gitignore 에 걸려 add 가 건너뛴`, `내가 고른 확인 항목` |
| 뭉뚱그린 형용사 | `기계적`, `유연한`, `효율적인` | 무엇이 어떻게 되는지로 - `사람 판단 없이 규칙만 보고` |

판단은 두 가지로 한다.

1. **소리 내어 읽어서 걸리면 고친다.** 말로 설명하지 못할 문장은 글로도 안 읽힌다.
2. **읽는 사람이 이 말을 전에 본 적 있나.** 없으면 한 번 풀어 쓴다.

반대로 **멀쩡한 말을 목록에 있다는 이유로 바꾸지 않는다.** `해당 항목`, `도출 방법` 같은 건
기술 문서에서 그대로 읽히는 표준어다. 이걸 `그 항목`, `어떻게 뽑나` 로 바꿨다가 더 어색해진 적이 있다.
고칠지는 문장을 읽어 보고 정하지, 단어를 찾아 바꾸는 식으로 정하지 않는다.

> 실제로 재어 봤다. 규칙 파일을 숨긴 세션과 비교했더니 이모지·`완벽하게` 같은 과장·`수행합니다` 는
> **양쪽 다 0건**이었다. 안 써도 원래 안 나오는 것들이라 목록에서 뺐다.
> 반면 표로 내기, 선택지 위치, 맨 앞 세 줄은 규칙이 있는 쪽에서만 지켜졌다.

## 안 쓰는 것

- 진행 상황 중계 (`"이제 X 를 확인하겠습니다"`) - 결과만 낸다
- 같은 내용을 표와 문장으로 두 번
- 근거 없는 완료 선언. `"배포 완료"` 가 아니라 `"이미지 v1.9.6, healthy, md5 일치"`
- 사람이 이미 아는 배경 설명
