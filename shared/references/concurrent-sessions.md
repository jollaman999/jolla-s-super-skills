# 동시 세션 충돌 방지

## 왜 필요한가

같은 프로젝트에 Claude 세션이 여러 개 붙어 있는 일이 실제로 자주 있다.
확인해 보면 한 머신에서 세션 5개가 동시에 돌고, 한 프로젝트에 2개가 붙어 있는 경우가 나온다.

이때 벌어지는 일:
- 내가 파일을 읽고 분석하는 사이에 **다른 세션이 그 파일을 고친다.** 낡은 내용을 근거로 판단하게 된다.
- 내가 `git add -A` 하면 **다른 세션의 미완성 변경이 같이 커밋된다.**
- 둘이 같은 파일을 편집해 서로의 변경을 덮어쓴다.
- 브랜치를 바꾸면 다른 세션의 작업이 통째로 사라진다.

## 확인 (작업 시작 전)

```sh
shared/scripts/session-guard.sh <프로젝트경로> [최근N분]
# exit 0 = 동시 세션 없음, 1 = 있음, 2 = 확인 불가
```

출력에는 다른 세션의 **최근 편집 파일 목록**과 현재 브랜치·워킹트리 상태가 같이 나온다.
이걸로 "겹치는지" 를 판단한다.

**동시 세션이 없으면 평소대로 진행한다.** 아래 절차는 있을 때만이다.

## 있을 때 - 스냅샷 방식

원본을 붙잡고 오래 분석하지 않는다. **떠서 나가고, 판단하고, 돌아와서 확인하고 적는다.**

```
1. 스냅샷    snapshot.sh take <proj>     -> /tmp/snap-xxx, 기준 해시 기록
2. 분석      스냅샷 안에서만 읽는다        <- 다른 세션이 원본을 고쳐도 무관
3. 판단      무엇을 어떻게 고칠지 확정
4. 드리프트  snapshot.sh drift <snap>    -> 그 사이 바뀐 파일 확인
5. 적용      원본에 패치
6. 정리      snapshot.sh clean <snap>
```

## 4단계에서 드리프트가 나오면

| 상황 | 행동 |
|------|------|
| 내가 고칠 파일과 **안 겹침** | 그대로 적용 |
| 내가 고칠 파일이 **바뀜** | **적용하지 않는다.** 그 파일을 다시 읽고 판단을 갱신한 뒤 적용 |
| HEAD 가 이동함 | 커밋이 생겼다. 내 판단의 전제가 바뀌었을 수 있으니 다시 확인 |
| 겹치는 파일이 많음 | 사용자에게 알리고 **기다릴지 진행할지 묻는다** |

## git stash 는 무조건 금지

동시 세션 여부와 무관하다. 실제 사고가 있었다.

> 2026-07-16, `git stash` -> 테스트 -> `git stash pop` 을 시도했다가 pop 이 충돌로 실패해
> **미커밋 작업 20개 파일이 워킹트리에서 사라졌다.** (stash 자체는 남아 수동 복구)

원인은 동시 세션이다. stash 로 워킹트리를 되돌리는 순간 다른 세션이 되돌려진 파일 위에 새로 쓰기 시작하고,
pop 할 때 충돌이 나며 양쪽 작업이 엉킨다. **워킹트리에는 항상 커밋 안 된 남의 작업이 있다고 가정한다.**

"내 변경 없이 baseline 이면 어떤가" 를 확인하려면:
- 테스트 리포트에서 실패 원인을 직접 읽는다 (`build/test-results/test/TEST-*.xml`)
- `git diff` 로 그 파일을 내가 건드렸는지 본다
- `git worktree add` 로 별도 워킹트리를 만든다
- 굳이 되돌려야 하면 먼저 백업한다 (`git diff > backup.patch`, 파일 복사) 후 즉시 되돌린다

## 커밋할 때

**매 커밋 전에 다른 세션이 만진 파일을 확인하고, 감지되면 그 분량은 빼고 커밋한다.**
나중에 그 세션이 끝난 뒤 다시 반영한다.

```sh
git add <내가 고친 파일들>        # git add -A 를 쓰지 않는다
git diff --cached --stat          # 커밋 직전에 무엇이 들어가는지 확인
```

브랜치 전환, `git checkout -- .`, `git reset --hard` 도 다른 세션의 작업을 날린다. 하지 않는다.

**zsh 함정**: zsh 는 따옴표 없는 변수를 단어 분할하지 않는다.
`git checkout $FILES` 는 전체가 하나의 pathspec 이 되어 실패한다. 루프나 배열을 쓴다.

## 원격 노드도 마찬가지다

같은 호스트에 다른 세션이 붙어 있을 수 있다. 24시간 넘게 도는 백그라운드 폴링이 실제로 관측된다.

- 재기동·배포 전에 그 호스트에서 **다른 작업이 도는지** 본다: `pgrep -af '<서비스명>|ansible|docker (build|load)'`
- 돌고 있으면 재기동하지 않는다. 사용자에게 알린다.

## 하지 말 것

- 동시 세션 확인 없이 긴 분석 시작
- 동시 세션이 있는데 `git add -A`
- **`git stash` (조건 없이 금지)**
- 동시 세션이 있는데 브랜치 전환·reset --hard
- 드리프트 확인 없이 패치 적용
- 다른 세션이 편집 중인 파일을 같이 편집
