# 그림

## 1. 원칙

| 규칙 | 근거 |
|------|------|
| **원본은 항상 SVG 다.** 손으로 직접 쓴다. 그림을 그리는 Python 도구는 쓰지 않는다 | 사용자: Windows 에 Python 이 없을 수 있다 |
| **원본은 산출물 폴더나 그 repo 에 둔다.** 스크래치패드에 두면 세션이 끝날 때 사라진다 | 생성 스크립트가 임시 폴더에 있다가 없어진 일 |
| **발표·외부용 그림은 Mermaid 구조도가 아니라 직접 설계한 그림이다** (3·4절) | "이런 그림 말고 발표용 그림 도식화된 그림 머메이드 같이 딱딱한 그런 구조도 말고" |
| **개발자 repo 문서이고 그 repo 에 그림 규약이 있으면 규약을 따른다** (Mermaid 정본 등). 사용자가 "발표용" 이라고 하면 위 줄이 먼저다 | Mermaid 로 낸 개발자 문서를 사용자가 받아들임 |
| **그림 종류와 시안 확인 여부는 처음 질문에서 정한다.** 시안을 고르면 한 장을 내고 방향을 받은 뒤 나머지를 그린다 | 사용자 지시 (처음에 시안 확인 여부를 묻는다) |
| **렌더해서 직접 본다.** 겹친 글자, 잘린 상자, 화살표, 줄 수 | 세 세션에서 렌더 후 고친 일 |
| **화살표는 좌표로 검사한다** (9절) | "그림 화살표 위치가 부정확해 잘 보고 다시 그려줘", "화살표가 겹쳐서 별처럼 보이니까 간격을 약간 벌려줘" |
| **보는 사람 PC 에 폰트가 없어도 같게 보여야 한다** (9절) | "svg 로도 가능해?" (PNG 대신 SVG 로 넣으며 폰트를 넣은 일) |
| **한글이 든 ASCII 그림을 넣지 않는다.** 한글 폭 때문에 상자 줄이 안 맞는다 | 이 PC 세션 교정 (원문 미보존) |
| **흰 배경, 상자와 화살표, 짧은 한글 라벨, 가운데 배치.** 구역을 넘는 화살표, 워터마크, 도구 이름, UML 다중도(`1..*`) 없음 | 이 PC 세션 교정 (원문 미보존) |
| **색은 중간 톤이다.** 네온·파스텔·칙칙한 색이 아니다. 고치라고 지목한 곳만 바꾼다 | 이 PC 세션 교정 (원문 미보존) |
| **한 장에 반대 방향 흐름(데이터 흐름과 설치 흐름)을 다 넣으면 선이 엉킨다.** 두 장으로 나눈다 | 개발자 문서 그림을 둘로 나눈 일 |

## 2. 출력별 넣는 법

| 출력 | 넣는 것 | 어떻게 |
|------|---------|--------|
| md | SVG 그대로 | `![전체 구조](figures/01-overview.svg)`. 경로는 **문서가 있는 폴더 기준**. 넣기 전에 9절로 검사하고 폰트를 넣는다 |
| hwp/hwpx | PNG | 9절 순서대로 검사·폰트를 넣은 뒤 `"$WH" svg2png -width-mm <영역 너비 mm> -o 01-overview.png 01-overview.svg` (기본 600 dpi) |
| pptx | 네이티브 도형 | 템플릿 덱의 도형으로 그린다. 도형으로 못 그리는 것만 PNG |
| GitHub `<img>` | SVG | 글자가 `foreignObject`(HTML) 이면 안 보인다. SVG `<text>` 로 쓴다 |

**hwp 영역 너비.** 그림이 들어갈 칸이나 본문의 너비다. 용지 너비에서 좌우 여백을 빼거나, 표 칸이면 그 칸 너비다.
값을 모르면 한글에서 확인하거나 사용자에게 묻는다. 어림값을 쓰면 보고에 적는다.
너비를 영역에 맞춰 뽑아야 한글이 늘리거나 줄이지 않고 600 dpi 그대로 넣는다.

**렌더해서 보는 법.** 그린 SVG 는 PNG 로 만들어 Read 로 연다.

```sh
"$WH" svg2png -width-px 1600 -o <스크래치패드>/check-01.png figures/01-overview.svg
```

확인용 PNG 는 스크래치패드에 둔다. 산출물이 아니다.
svg2png 는 why-hwp 에 든 엔진으로 그려서 브라우저가 필요 없다. **글자는 SVG 에 넣은 폰트로만 그린다.** PC 에 깔린 폰트는 쓰지 않으므로 9절 2번(`svgfont`)을 먼저 돌린다. 폰트가 없는 SVG 는 글자 없이 그려지고 stderr 에 경고가 나온다.

## 3. 스타일 A: 발표 슬라이드형

코드를 모르는 회의 참석자에게 보이는 그림. 사용자가 받아들인 것을 PNG 를 보고 적은 사양이다.

| 요소 | 사양 |
|------|------|
| 크기 | 16:9. 원본 1600×960 |
| 배경 | 아주 연한 회청색 |
| 제목 | 왼쪽 위, 굵은 큰 글씨 |
| 한 줄 메시지 | 제목 바로 아래 회색 한 줄. 그림이 말하려는 결론 |
| 범례 | 오른쪽 위. 신호마다 선 색 (예: 메트릭 파랑, 로그 초록, 트레이스 주황, 설치·제어 보라 점선) |
| 구역 | 번호 원(1~4)이 붙은 큰 구역을 흐름 방향(왼쪽 → 오른쪽)으로. 구역마다 연한 배경색. 주인공 구역 하나만 진한 남색 배경에 흰 글자 |
| 카드 | 구역 안 흰 둥근 카드. 왼쪽 위 선 아이콘(서버, DB, 사람, 종), 굵은 이름, 회색 설명 1~2줄, 아래 알약 모양 태그 |
| 저장소 카드 | 왼쪽에 신호 색 세로 띠 |
| 화살표 위 설명 | 작은 흰 둥근 상자 안 짧은 문장 |
| 제어 경로 | 보라 점선, 아래쪽을 크게 돌아감. 가운데 알약 하나 |
| 글꼴 | 본고딕 계열 (Noto Sans CJK KR) |

그림마다 구성의 예.

| 그림 | 구성 |
|------|------|
| 전체 구조 | 대상 → 저장 → 관리 서버 → 본체, 4구역 |
| 데이터 흐름 | 수집 → 저장 → 조회 → 화면, 4단계 가로 |
| 종류별 비교 | 종류를 세로 줄로. 줄마다 같은 칸(어디서, 무엇을, 어떻게) |
| 두 갈래 흐름 | 갈래를 위아래로 → 한 곳에서 만남 → 화면 |
| 배포·제어 | 길 셋을 나란히 |
| 단계 | 5단계 가로 + 아래에 조건과 빈 곳 |

## 5. 데이터 모델 그림

| 규칙 | 근거 |
|------|------|
| 필드를 위에서 아래로 한 줄씩 적는다 | "필드들믈 세로로 쭉 나열하고 배열의 어떻게 참조되는지 보였으면 하는데 * 하고 1...* 처럼 이상하게 되어있는데?" |
| 배열 필드 줄에서 담기는 상자로 화살표를 긋는다 | 같은 발화 |
| `1..*`, `*`, `0..1` 같은 UML 표기 대신 말로 쓴다. 개수는 **실제 스키마(최소·최대 개수)에서 가져온다.** 확인한 최소가 1 이면 "1개 이상", 확인 못 했으면 "여러 개"(배열) 까지만. 빈 배열이 정상인 API 에 "1개 이상" 을 쓰면 받는 쪽이 빈 결과를 오류로 다룬다 | 같은 발화, 외부 리뷰 |

| 요소 | 사양 |
|------|------|
| 제목·부제 | 무엇이 담기는지 + "필드를 위에서 아래로 적었다. 파란 줄은 배열이고, 화살표가 그 배열에 담기는 항목을 가리킨다" |
| 묶음 소제목 | 어느 API 가 돌려주는지 |
| 상자 | 진한 남색 머리(굵은 타입 이름 + 작은 한글 뜻) + 흰 몸통 |
| 몸통 한 줄 | 필드 하나, 세 칸: 이름(굵게) / 타입 / 예시 값(흐린 회색, 오른쪽 정렬) |
| 배열 필드 줄 | 연한 파랑 배경, 타입이 파란 글씨(`Item[]`), 예시 칸에 개수(위 규칙대로, 모르면 비움). 줄 오른쪽 끝에서 파란 꺾은 화살표가 담기는 상자의 머리로, 화살표 위 "여러 개" |
| id 로 찾는 관계 | 주황 점선 화살표 + "같은 id 를 찾아 씀", 양쪽 줄을 연한 주황으로 |
| 실제 한 건 | 빈 곳에 실제 데이터 한 건(JSON) 상자. 고정폭 글꼴, 줄임 |
| 범례 | 파란 실선 "배열이 담는 항목", 주황 점선 "id 로 찾아 씀" |

그림 아래 문장으로 규칙(어떤 필드가 어디에 있어야 하는지, 값의 우선순위)을 쓴다.

## 6. SVG 쓰는 법

직접 쓰는 SVG 의 뼈대다. 화살촉은 선 색마다 `marker` 를 하나씩 둔다.

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1600 900" width="1600" height="900"
     font-family="'Noto Sans KR','Noto Sans CJK KR','Malgun Gothic',sans-serif">
  <defs>
    <marker id="m-blue" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7"
            orient="auto-start-reverse"><path d="M0,0L10,5L0,10z" fill="#2563eb"/></marker>
  </defs>
  <rect width="1600" height="900" fill="#ffffff"/>
  <text x="40" y="58" font-size="32" font-weight="700" fill="#0f172a">제목</text>
  <text x="40" y="92" font-size="18" fill="#475569">이 그림이 말하려는 결론 한 줄</text>

  <rect x="400" y="140" width="620" height="560" rx="22" fill="#eff6ff" stroke="#3b82f6" stroke-width="2"/>
  <text x="424" y="176" font-size="21" font-weight="700" fill="#1d4ed8">패널 이름</text>

  <rect x="430" y="200" width="260" height="100" rx="14" fill="#ffffff" stroke="#64748b" stroke-width="2"/>
  <text x="560" y="243" font-size="19" font-weight="700" fill="#0f172a" text-anchor="middle">상자 이름</text>
  <text x="560" y="270" font-size="14" fill="#475569" text-anchor="middle">설명 한 줄</text>

  <rect x="430" y="350" width="260" height="100" rx="14" fill="#1e3a8a" stroke="#1e3a8a" stroke-width="2"/>
  <text x="560" y="408" font-size="19" font-weight="700" fill="#ffffff" text-anchor="middle">강조 상자</text>

  <path d="M560,300 L560,348" stroke="#2563eb" stroke-width="2.5" fill="none" marker-end="url(#m-blue)"/>
</svg>
```

| 지킬 것 | 왜 |
|---------|-----|
| 모든 글자는 `<text>` | `foreignObject` 는 GitHub `<img>` 와 일부 렌더러에서 안 보인다 |
| 글자마다 `font-weight` 를 적는다 | 폰트를 넣을 때 굵기별로 글자를 모은다 (9절) |
| 상자 글자는 `text-anchor="middle"`, x 는 상자 가운데 | 줄마다 가운데 정렬 |
| 줄 간격은 글자 크기 × 1.45 | 사용자가 받아들인 그림의 값 |
| 좌표는 정수 | 화살표 끝점을 상자 테두리에 정확히 맞추기 쉽다 |

## 7. 화살표 배치 요령

| 요령 | 예 |
|------|-----|
| 끝점은 받는 상자 테두리 좌표에서 화살촉 길이만큼 덜 간 곳 | 상자 위쪽이 y=350 이면 끝을 348 로 |
| 꺾은 화살표(`M.. L.. L..`)는 상자 사이 빈 통로로만 지나게 한다 | 통로 x 를 먼저 정하고 꺾는다 |
| 여러 화살표가 한 점에 모이면 출발·도착점을 몇 픽셀씩 벌린다 | 같은 상자로 들어오는 셋을 상자 폭에 고르게 |
| 글자 목록에서 화살표를 시작하지 않는다 | 묶음 괄호나 상자를 그리고 거기서 시작한다 |
| 반대 방향 흐름은 다른 장으로 | 1절 마지막 줄 |

## 8. Mermaid 를 쓸 때

개발자 repo 문서에서 그 repo 가 Mermaid 를 쓰거나 사용자가 고른 경우만이다.

| 규칙 | 근거 |
|------|------|
| 라벨을 HTML 이 아니라 SVG 텍스트로 렌더한다 (최상위 설정 `htmlLabels: false`). GitHub 에서 `<img>` 로 넣어도 글자가 보인다 | 개발자 문서 그림 세션 |
| 소스 `.mmd` 와 렌더 `.svg`·`.png` 를 같은 이름으로 같은 폴더에 | 같은 세션 |
| 렌더 도구가 깨져 있으면 렌더를 못 했다고 알린다. 렌더 안 한 Mermaid 그림을 본 것처럼 보고하지 않는다 | (판단) |

## 9. 폰트 넣기와 검사

why-hwp 의 `svgfont`·`svgcheck` 로 한다 (why-hwp v0.3.0 이상). 둘 다 TrueType(`.ttf`) 폰트만 받는다.
CFF(`.otf`), 가변 폰트(`NotoSansKR-VF.ttf` 같은 것), `.ttc` 는 거절한다.

| 순서 | 명령 | 무엇을 보나 |
|------|------|-------------|
| 1 | `"$WH" svgcheck figures/01-overview.svg` | 글자가 상자를 넘침, 글자끼리 겹침, 화살표 끝이 어느 상자에도 안 닿음, 화살표가 남의 상자를 지나감 = 위반(종료 코드 1). 화살촉 셋 이상이 한 점에 몰림 = 경고 |
| 2 | `"$WH" svgfont -w figures/01-overview.svg` | 그 그림에 쓴 글자만 담은 폰트를 굵기별로 SVG 안에 넣는다. 다시 돌려도 같은 파일이 나온다 |
| 3 | `"$WH" svg2png -width-px 1600 -o <스크래치패드>/check-01.png figures/01-overview.svg` 후 Read | 눈으로 본다. 1번이 못 잡는 것(곡선 화살표, 색, 줄 수, 전체 균형) |
| 4 | hwp 면 `"$WH" svg2png -width-mm <영역 mm> -o figures/01-overview.png figures/01-overview.svg` | 넣을 PNG |

| 함정 | 어떻게 |
|------|--------|
| 쓸 폰트를 못 찾음 | `svgfont`·`svgcheck` 는 OS 폰트 폴더에서 Noto Sans KR → 나눔고딕 → 나눔스퀘어 → 맑은 고딕 순으로 찾고, 그다음 why-hwp 글꼴 캐시를 본다. 그래도 없으면 나눔고딕(OFL)을 받아 쓴다. 다른 폰트를 쓰려면 `-regular`·`-bold` 로 파일을 준다. **어느 폰트가 들어갔는지 보고한다** (stderr 첫 줄) |
| 폰트 라이선스 | 공개 문서에 넣는 폰트는 사용자가 정한다. Noto Sans KR 은 OFL 이다. 맑은 고딕은 "문서에 넣기 허용" 표시가 있지만 공개 배포는 따로 판단할 일이다. 나눔스퀘어는 파일에서 라이선스를 확인하지 못했다 |
| 폰트에 모양이 없는 글자 | `svgfont` 가 stderr 에 알린다. 나눔스퀘어는 자주 쓰는 2350자 밖의 한글을 빈칸으로 그린다. 알림이 나오면 다른 폰트로 바꾸거나 낱말을 바꾼다 |
| `svgcheck` 가 못 보는 것 | 곡선·호가 든 path, translate 가 아닌 transform. notes 에 나온다. 그 부분은 3번에서 눈으로 본다 |
| 일부러 그렇게 그린 선 | 시간축·묶음선이 위반으로 나오면 고치지 말고 보고에 예외로 밝힌다 |
| 폰트를 넣은 SVG 를 다시 고침 | 고친 뒤 2번을 다시 돌린다. 새로 쓴 글자가 폰트에 없으면 대체 글꼴로 나온다 |
