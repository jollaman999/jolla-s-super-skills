# 쓰기 규칙

규칙마다 근거를 단다. 근거는 실제로 있었던 실패의 모양을 한 줄로 적는다. 대화 원문은 옮기지 않는다.
실패 모양이 남지 않은 교정은 `세션 교정 (상세 미보존)` 으로 적는다.
근거가 받쳐 주는 범위를 넘겨 넓힌 것은 `(판단)` 으로 표시한다.
규칙 문구가 근거보다 넓어져 무엇을 근거로 정했는지 사용자가 다시 물어야 했던 적이 있어서다.

근거에는 기관·제품 이름을 쓰지 않는다.

## 1. 시작할 때

| 규칙 | 근거 |
|------|------|
| **독자를 먼저 정하고 한 줄로 알린다.** 발표 청중, 다른 기관 개발자, 그 repo 개발자, 제출처에 따라 아래 규칙이 갈린다 | 독자를 정하지 않고 코드 중심으로 썼다가 발표용으로 다시 썼다 |
| **"기존에 ~ 했던거 처럼", "이 형식에 맞게" 면 이전 산출물이나 붙여 넣은 양식을 찾아 구성을 그대로 따른다.** 절이 하나뿐이어도 이전 초안에 있던 제목 줄까지 맞춘다 | 이전 MR·Jira 초안의 형식과 붙여 넣은 예시의 구성을 따르지 않아 다시 썼다 |
| **원본을 읽고 쓴다.** 코드, PDF·양식, 상대 기관 자료를 직접 연다. 사용자가 가정한 연결 지점이 원본과 다르면 쓰기 전에 그것부터 말한다 | 협업 기관 자료를 따로 열어 대조해야 했던 일 |
| **못 읽은 자료가 있으면 바로 알린다.** 추정으로 채우지 않는다 | 받은 계획 파일들의 내용을 문서에서 빠뜨렸다 |
| **양식을 채우는 일이면 "양식 어느 절·표·칸에 무엇을" 체크리스트를 먼저 만든다.** 작업 메모와 보고에 두고, 제출본 안에는 넣지 않는다 | 세션 교정 (상세 미보존). 제출본에서 뺀다는 것은 (판단) |

## 2. 내용

| 규칙 | 근거 |
|------|------|
| **발표·외부 기관용은 코드가 아니라 목적과 동작을 쓴다.** 파일 경로, 줄 번호, 함수 이름을 뺀다 | 발표·외부 기관용 문서를 코드 설명으로 써서 동작 설명으로 다시 썼다 |
| **최종본만 쓴다.** "N차 개편", 개편 이력, 날짜 붙은 결정 경위, 이전 검토·이전 PoC 를 넣지 않는다. 날짜로 바꿔 쓰는 것도 아니다 | 개편 이력, 이전 PoC 검토, 날짜 붙은 결정 경위를 넣어 작업 기록처럼 읽혀 뺐다 |
| 날짜를 남기는 곳은 근거의 날짜(확인한 날, 권고 날짜)뿐이다 | Jira 초안의 "근거: ... (확인 날짜)" 를 사용자가 받아들임 |
| **맨 위에 메타 블록(대상·작성일·범위·그림 원본·근거)을 두지 않는다.** 제목 다음은 바로 "한 장 요약" | 맨 위에 메타 블록을 넣었다가 지웠다 |
| 리뷰 자료는 "무엇을 기준으로 봤나" (기준 소스·버전) 한 줄을 남겨도 된다 | 리뷰 문서의 기준 표를 사용자가 지적하지 않음 (판단) |
| **처음 나오는 도구·용어는 무엇인지와 어떻게 동작하는지 풀어 쓴다** | 처음 나오는 도구 이름을 풀지 않아 무엇인지와 동작을 덧붙였다 |
| **대화에서 답한 내용, 시험 결과, 실제 화면, 사용자의 설계 질문에 대한 답은 문서에도 넣는다** | 시험 결과, 대화에서 답한 내용, 설계를 고른 이유를 문서에서 빠뜨려 덧붙였다 |
| **구조를 바꾸면 문서와 그림을 같은 턴에 고친다** | 구조를 바꾼 뒤 문서가 따라 갱신됐는지 사용자가 다시 물어야 했다 |
| **우리 몫과 협업 기관 몫을 가른다.** 경계에 걸린 문구는 근거(코드 위치, 상대 자료 쪽수)를 대고 고친다 | 협업 기관 몫을 우리 쪽 일로 적어 경계를 다시 갈랐다 |
| **남의 몫은 쓰지 않는다.** 남이 주관하는 목표·지표를 우리 문서에 채우지 않는다 | 우리가 고려할 필요 없는 요소와 다른 기관이 주관하는 목표를 우리 문서에 넣었다 |
| **미정은 "협의 필요" 로 둔다.** 상대 자료끼리 어긋나면 한쪽을 고르지 않고 둘 다 적는다 | 상대 기관 자료 안의 호출 방향이 두 가지였던 일 |
| **분담은 최신 근거로 쓴다.** 회의록·담당 그림·사용자 말이 계획서보다 앞이다 | 세션 교정 (상세 미보존) |
| **이름은 앞으로의 범위를 생각해 짓는다.** 등록 이름은 이번에 실제로 한 일로 좁히고 다음 해 몫을 남긴다 | 등록 이름을 넓게 지어 다음 해 등록에 지장이 생길 수 있어 다시 지었다 |
| **한 문서에 두 종류를 섞지 않는다.** 발표·리뷰용(그림과 핵심 세 줄)과 근거 문서(`file:line`, 기능별 상세)를 나눈다 | 발표용 그림과 근거 상세를 한 문서에 섞어 둘로 나눴다 |
| **리뷰 문서는 결정하지 않는다.** "정할 것" 만 표로 모으고 그렇게 밝힌다 | 리뷰 자료를 요청한 세션에서 사용자가 받아들인 형태 (판단) |
| **결정을 쓸 때는 후보·어떻게 동작하나·얻는 것·잃는 것·고른 이유를 쓴다** | 두 구조를 비교한 결정에서 고른 이유를 빠뜨려 덧붙였다 |
| **요구사항은 추상적으로 쓴다.** 구현 방식이 아니라 무엇이 되어야 하는지 | 세션 교정 (상세 미보존) |
| **제안서는 특정 제품·도구·업체 이름 대신 기능 이름으로 쓰고, 끝에 금지어 검사를 한다.** 내부 계획 문서는 자산 이름을 써도 된다 | 세션 교정 (상세 미보존) |
| **수치는 약속이다.** 확실한 하한으로 쓴다 ("4+종") | 세션 교정 (상세 미보존) |
| **사용자가 준 KPI 후보, 표 양식, 배정은 바꾸지 않는다** | 세션 교정 (상세 미보존) |
| **최소 분량으로 쓴다.** 검토 의견은 "어디를 무엇으로" 만, Jira 는 한 건 | 세션 교정 (상세 미보존) |
| **근거 없는 칸은 비워 두지 말고 "추정" 또는 "원본 확인 필요" 로 표시한다** | 세션 교정 (상세 미보존) |
| **모르는 값은 지어내지 않고 `<...>` 로 비운다.** 토큰 같은 비밀값은 "별도로 전달" 로 쓴다 | 초안 세션들에서 사용자가 받아들인 형태 |
| **받는 사람이 다시 물을 만한 것은 초안에 한 줄 미리 넣는다** | 메일 초안을 파일로 뽑을 때 한 줄 더한 것을 받아들임 |

## 3. 남에게 넘기는 문서에서 뺄 것

`~/.claude/skills/shared/references/reporting.md` 5절을 따른다. 요지만 둔다.

| 물음 | 아니면 |
|------|--------|
| 이 문단으로 읽는 사람에게 할 일이 생기나 | 뺀다 |
| 이 사람이 정할 수 있는 것인가 | 정할 사람이 따로 있으면 `고려 대상` 이라고만 |
| 이 문단이 읽는 사람이 판단할 재료인가 | 별도 파일로 뺀다. 내가 확인 못 한 것이 여기 걸린다 |
| 내 조사 과정·수치를 다시 뽑는 법인가 | 뺀다 |

읽는 사람이 손을 움직일 사람이면 할 일로 쓴다 (`~할 수 있습니다` 가 아니라 `~하세요`).

## 4. 공개 문서

| 규칙 | 근거 |
|------|------|
| **공개 문서는 내부 이름·사내 경로·IP·계정을 뺀다.** 문서와 그림 원본을 내부 이름 목록으로 grep 해 0건을 확인한다 | 소스 상세가 든 문서를 공개하려다 앞으로의 계획만 남겨 공개본으로 다시 썼다 |
| **그림·캡처 속 글자는 grep 에 안 잡힌다.** 하나씩 눈으로 본다. 이름이 찍힌 캡처는 **이미지 파일 자체에서 그 픽셀을 지운 판**(다시 찍거나 잘라 내거나 칠한 PNG)으로 바꿔 넣는다. 슬라이드·문서 위에 도형을 덮는 것으로 끝내지 않는다. 덮어도 원본 이미지가 `ppt/media/`·`word/media/`·`BinData/` 에 그대로 남는다 | 워크샵 자료에서 화면 19장을 눈으로 본 일, 외부 리뷰 |
| **화면에 안 보이는 곳도 공개된다.** 공개본을 내기 전에 본다: pptx 슬라이드 노트·숨긴 슬라이드·숨긴 개체·`media/` 의 모든 이미지, docx 메모·변경 내용·`media/`, hwp/hwpx 메모·지운 글·머리말·꼬리말 (`hwp.md` 5절). 못 본 곳은 "확인 못 함" 으로 보고한다 | 외부 리뷰 |
| **작업본과 공개본을 나눈다.** 메모·변경 추적·원본 캡처가 남은 작업본을 그대로 공개하지 않는다. 공개본은 따로 만들고 위 검사를 그 파일에 한다 | 외부 리뷰 |
| **써도 되는 이름은 사용자가 정한다.** 회사 이름처럼 남겨도 되는 것을 내가 지우지 않는다 | 회사 이름을 남겨도 되는지 사용자가 정한 일 |
| 다른 과제 이름을 쓰지 않기로 한 자료는 기능 이름으로 쓴다 ("인프라 그룹 관리", "연동 계층", "기반 오픈소스"). 지시받지 않고 적용했으면 그렇다고 밝힌다 | 과제 회의에서 정한 표기 규칙을 따른 일, 다른 문서에 임의 적용하고 밝힌 일 |
| PR 본문에 `## Summary`, `## Test plan`, 체크박스, 생성 도구 문구를 쓰지 않는다 | 전역 규칙 (`CLAUDE.md` PR 절) |

## 5. 함께 고칠 것

| 규칙 | 근거 |
|------|------|
| **같은 내용이 든 문서를 처음부터 전부 찾아 같이 고친다.** 언어판 전부, reference 문서, README, 제출 명세서, 발표 자료 | 같은 내용이 든 reference 문서, README, 다른 정리 문서를 같이 고치지 않아 따로 지시를 받았다 |
| **문서를 지우거나 옮기면 그 문서를 가리키던 링크를 전부 고친다.** 지운 내용이 어디에 남는지 보고한다 | 옛 설계 문서를 지우며 링크 2곳을 고친 일 |
| **그림 경로는 문서가 있는 폴더 기준이다.** 문서를 옮기면 그림 경로가 실제 파일에 닿는지 전부 검사한다 | 문서를 옮긴 뒤 그림 경로가 깨졌다 |

## 6. 형식과 고치는 방식

| 규칙 | 근거 |
|------|------|
| **출력 형식 말은 그대로 따른다.** "txt" 면 txt, "계단식" 이면 `-` 들여쓰기 목록, "뽑아" 면 파일 | md 로 냈다가 txt 로, 표로 냈다가 계단식 목록으로 다시 냈다 |
| **표를 목록으로 바꿔 달라면 내용은 그대로 두고 모양만 바꾼다** | 표를 계단식 목록으로 바꾼 일 |
| **위치를 지목한 요청은 그대로 고친다.** 앞선 지시와 달라도, 지금 화면이 맞다고 반박하지 않는다 | 위치를 지목한 요청(언어 전환 링크 위치)을 한 번에 따르지 않아 같은 요청을 두 번 받았다 |
| **초안에 약속(다음 릴리즈에 하겠다 등)이 들어가면 따로 짚어 보낼지 묻는다.** 상황이 바뀌면 초안을 새로 쓴다 | Slack 답변 초안에서 짚은 것을 사용자가 받아들임 |
| **사용자에게 하는 말은 한국어다.** 영어 문서를 쓰는 중이어도 | 영어 문서를 쓰던 중 영어로 답해 한국어로 다시 정리했다 |
| 번역은 `reporting.md` 7절 | 전역 규칙 |
| 한 번에 한두 값을 고치는 요청이 이어지면 지목한 곳만 바꾼다 | 전역 규칙 (`CLAUDE.md` "화면을 조금씩 고치는 요청") |

## 7. 실제 화면 캡처

| 규칙 | 근거 |
|------|------|
| **비밀값을 가린다.** 전화번호, 웹훅 주소, IP, 토큰 | 세션 교정 (상세 미보존) |
| 캡처 날짜·환경을 적고, 비어 있는 칸이 데이터가 없어서인지 밝힌다 | 리뷰 문서에 캡처를 넣을 때 사용자가 받아들인 형태 |

| API·Swagger 화면보다 실제 결과 화면을 넣는다 (발표) | 세션 교정 (상세 미보존) |

## 8. "된다" 고 쓴 것

| 규칙 | 근거 |
|------|------|
| **빠른 시작처럼 "이렇게 하면 된다" 고 쓴 명령은 직접 돌려 본다.** 못 돌린 것(다른 OS, 큰 스택)은 못 돌렸다고 밝힌다 | 외부 README 와 4개 언어 README 세션에서 사용자가 받아들인 형태 |
