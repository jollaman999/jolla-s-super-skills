# 처음 질문과 분석

쓰기 전에 자료를 분석하고, 그 결과를 근거로 한 번에 묻는다.
담당·기관·파일명은 문서마다 다르므로 이 skill 에 적어 두지 않고 매번 자료에서 뽑는다 (사용자 지시).

예에 나오는 `<기관 A>`, `<회사>`, `<과제>` 는 자리표시자다. 실제 이름은 자료에서 읽는다.

## 1. 분석

| 순서 | 뽑을 것 | 어디서 | 결과 |
|------|---------|--------|------|
| 1 | 양식의 절·표·칸 | `why-hwp info` (표와 크기), `why-hwp text` (칸 글자와 위치) | 칸 목록 |
| 2 | 담당 표기 | 1.1 | 표기 · 뜻 · 나온 곳 · 개수 |
| 3 | 협업 기관 | 1.2 | 기관 · 맡은 것 · 근거 |
| 4 | 최신 분담 근거 | 1.3 | 근거마다 날짜와 우선순위 |
| 5 | 파일명·버전 규칙 | 1.4 | 규칙 한 줄과 이번 이름 후보 |
| 6 | 예시의 스타일 | 1.5 | 끝말, 깊이, 개수, ID 체계 |
| 7 | 기존 변경 추적·메모 | `why-hwp info` | 개수와 저자 |
| 8 | 올릴 곳·공개 여부 | 사용자 말, repo 공개 여부, 양식의 제출처 | 공개 / 내부 / 제출 |

### 1.1 담당 표기

정부과제 양식은 칸마다 누가 쓰는지를 `(A)`, `(A/B)` 같은 표기로 붙인다.

```sh
"$WH" info 양식.hwpx          # 담당 표기와 나온 위치가 나온다
"$WH" text 양식.hwpx | grep -n '※\|담당\|주관\|참여'   # 범례 찾기
```

| 할 일 | 어떻게 |
|-------|--------|
| 표기를 모은다 | hwpx·docx 는 `info` 의 담당 표기 목록. md 는 본문에서 괄호 표기를 grep 으로 찾는다 |
| 범례를 찾는다 | 표 아래·문서 앞의 "※ A: ..., B: ..." 같은 줄. 없으면 사업계획서의 참여기관 표 |
| 우리 표기를 정한다 | 범례에서 우리 기관이 어느 글자인지. 범례가 없으면 **추정하지 않고 묻는다** |
| 공동 표기 `(A/B)` | 그 칸에서 우리 몫이 무엇인지 따로 본다. 칸 전체를 우리 몫으로 쓰지 않는다 |

결과를 표로 만든다. 질문할 때 이 표가 근거가 된다.

| 표기 | 뜻 (범례) | 나온 곳 | 개수 |
|------|-----------|---------|------|
| (A) | `<기관 A>` | 3장 표 1·2, 4.1절 | 12 |
| (A/B) | `<기관 A>`·`<기관 B>` 공동 | 4.2절 | 3 |
| (B) | `<기관 B>` | 3장 표 3 | 7 |

### 1.2 협업 기관

| 어디서 | 무엇 |
|--------|------|
| 범례, 참여기관 표 | 기관 이름과 역할 |
| 회의록 참석자·결정 | 바뀐 역할 |
| 담당 그림 (모듈별 담당을 그린 그림) | 모듈마다 누구인지 |
| 상대 기관 발표자료 | 상대가 스스로 말한 범위. 쪽수를 근거로 적는다 |

**사용자가 가정한 연결 지점이 상대 자료와 다르면 쓰기 전에 그것부터 말한다.**
상대 자료 안에서도 어긋나면 한쪽을 고르지 않고 둘 다 적어 "협의 항목" 으로 둔다.

### 1.3 최신 분담 근거

계획서는 처음에 쓴 것이고 분담은 그 뒤에 바뀐다. 근거마다 날짜를 붙이고 우선순위대로 본다.

| 우선 | 근거 | 날짜를 읽는 곳 |
|------|------|----------------|
| 1 | 사용자가 이번에 한 말 | 대화 |
| 2 | 회의록, 담당 그림 | 파일명의 날짜, 본문의 회의 날짜 |
| 3 | 제안서, 사업계획서 원문 | 표지, 파일명 |

- 파일명에 날짜가 없으면 `ls -l --time-style=+%Y-%m-%d` 로 수정일을 보되 "수정일 기준" 이라고 밝힌다.
- 원문 기준과 회의 기준이 다르면 **둘을 나눠 적는다.** 어느 쪽으로 쓸지는 질문에 넣는다.
- 근거가 계획서뿐이면 그렇다고 말하고, 바뀐 분담이 있는지 묻는다.

### 1.4 파일명·버전 규칙

같은 폴더와 위 폴더의 파일 목록에서 뽑는다.

```sh
ls -1 "<자료 폴더>" "<자료 폴더>/.."
```

| 볼 것 | 예 |
|-------|-----|
| 날짜 자리와 모양 | 맨 앞 `YYMMDD` |
| 날짜가 안 정해졌을 때의 표기 | `YYXXXX` 처럼 연도만 두고 나머지를 `X` 로 |
| 조직 약칭 | 괄호 안 `(<회사 약칭>)` |
| 과제·연차·차수 | `<과제> NN년도 N차` |
| 문서 종류 | `워크샵 발표 자료`, `실적보고서` |
| 버전 | 끝의 `vX.Y`. 가장 큰 버전 다음 번호를 제안한다 |

뽑은 규칙은 한 줄로 쓰고 이번 이름을 채워서 보인다.

```
규칙: YYMMDD (<회사 약칭>) <과제> NN년도 N차 <문서 종류> vX.Y.<확장자>
이번: 26XXXX (<회사 약칭>) <과제> 26년도 2차 워크샵 발표 자료 v1.0.pptx   (날짜 미정)
```

**규칙이 하나로 안 모이면 후보를 둘 내고 묻는다.** 섞어서 새 규칙을 만들지 않는다.

### 1.5 예시의 스타일

| 볼 것 | 어떻게 |
|-------|--------|
| 끝말 | 예시 문단의 마지막 낱말. "~개발", "~구현", "~함", 명사형 |
| 깊이 | 항목 아래 몇 단계까지 내려가는지, 단계마다 몇 개인지 |
| 괄호 | 괄호 보충을 쓰는지 |
| ID 체계 | `REQ-001`, `SFR-01` 같은 번호 모양과 이어지는 번호 |
| 분량 | 칸 하나에 몇 줄인지. 렌더한 모양(PDF)으로 본다 |

### 1.6 맞는 해의 자료

"N차년도 실적", "올해 성과" 처럼 해를 가리키면 그해 자료만 근거로 쓴다.
그해 실적은 그해 하반기(2차) 워크샵·보고 자료에 있다. 다른 해 자료가 섞이면 질문에서 짚는다.

## 2. 질문 목록

| # | 묻는 것 | 추천 답을 정하는 근거 | 기본 추천 |
|---|---------|----------------------|-----------|
| 1 | 어느 담당 부분을 쓸지 | 1.1 표 | 우리 표기가 붙은 칸, 공동 칸은 우리 몫만 |
| 2 | 협업 기관 몫을 넣을지 | 1.2, 1.3 | 넣지 않는다. 경계는 "협의 필요" |
| 3 | 독자 | 올릴 곳, 자료의 성격 | 아래 독자 표에서 하나 |
| 4 | 올릴 곳·공개 여부 | 1번 표 8행 | 공개면 내부 이름 빼기 |
| 5 | 그림 종류 | 독자, repo 의 그림 규약 | 발표·외부용은 직접 그린 흐름 그림, 개발자 repo 는 그 repo 규약 |
| 6 | 그림 시안 확인 | 그림 장수, 처음 맞추는 스타일인지 | 처음 맞추는 스타일이거나 여러 장이면 시안 한 장 먼저 (판단) |
| 7 | 파일명 | 1.4 | 규칙에 맞춘 이름 |
| 8 | 이름 표기 | 문서 종류, 자료의 기존 표기 | 자료가 쓰는 표기를 따른다 |
| 9 | 변경 추적 | 남의 양식인지, 기존 변경 추적이 있는지 | 남의 양식이면 켠다 |
| 10 | 출력 형식 | 사용자 말, 원본 형식 | 말한 형식. 없으면 원본 형식 |

**독자**

| 독자 | 쓰는 법 |
|------|---------|
| 그 repo 개발자 | 표 중심, `file:line` 근거, repo 규약 그림 |
| 협업 기관 | 코드가 아니라 동작과 API. 그쪽이 할 일 |
| 소스를 처음 보는 사람 | 무엇인지부터. 처음 나오는 말을 푼다 |
| 결정권자 | 기술 요지만. 결정할 것 표 |
| 제출처 (심사·관리 부서) | 양식 칸 그대로, 칸마다 쓰는 방식 그대로 |

**이름 표기는 문서마다 다르다.** 같은 사용자가 한 문서에서는 회사 이름을 그대로 쓰게 했고
("<회사> 라고 쓰면 돼"), 다른 문서에서는 다른 과제 이름을 기능 이름으로 바꾸게 했다.
그래서 매번 묻는다.

## 3. 묻는 형식

분석 근거를 질문 옆에 붙이고 추천 답을 쓴다. "다 추천대로" 한 마디로 닫히게 한다.

```markdown
자료 6개를 열었습니다. 못 연 것은 없습니다.

| # | 정할 것 | 분석한 것 | 추천 |
|---|---------|-----------|------|
| 1 | 쓸 담당 부분 | 양식에 (A) 12곳, (A/B) 3곳, (B) 7곳. 범례상 A 가 우리입니다 (3쪽 표 아래 ※) | (A) 12곳과 (A/B) 3곳의 우리 몫 |
| 2 | 협업 기관 몫 | 회의록(10월)에서 4.2절 성능 목표는 <기관 B> 주관으로 바뀜. 계획서 원문은 공동 | 넣지 않고 "협의 필요" 로 표시 |
| 3 | 독자 | 제출처가 전담기관 | 제출처. 양식 칸 그대로 |
| 4 | 그림 | 3.1절 칸에 그림 자리 1곳, 칸 너비 약 150mm (한글에서 확인 필요) | 흐름 그림 1장, PNG 600dpi |
| 5 | 그림 시안 | 1장뿐 | 끝까지 그리고 한 번에 확인 |
| 6 | 파일명 | 폴더 파일 9개가 `YYMMDD (<회사 약칭>) <과제> ... vX.Y` | `26XXXX (<회사 약칭>) <과제> 26년도 실적보고서 v1.0.hwpx` |
| 7 | 변경 추적 | 원본에 변경 추적 0건, 메모 4건 | 켠다. 메모는 그대로 둔다 |

이렇게 진행할까요?
```

| 지킬 것 | 왜 |
|---------|-----|
| 분석한 것 칸에 숫자·쪽·절을 쓴다 | "확인했습니다" 만으로는 사용자가 맞는지 못 본다 |
| 근거가 없으면 "판단 근거 없음, 정해 주세요" | 억지로 추천을 채우지 않는다 |
| 못 연 자료가 있으면 표 위에 먼저 | 그 자료 없이 진행할지가 첫 결정이다 |
| 마지막 줄은 "이렇게 진행할까요?" | 사용자가 정한 형식이다 |

## 4. 답을 받은 뒤

- 답을 그대로 쓰기 기준으로 삼는다. 쓰다가 답과 어긋나는 것이 나오면 멈추고 알린다.
- 답이 새 질문을 열면 그 질문만 다음 라운드로 묻는다.
- 쓰기 시작할 때 독자와 종류를 한 줄로 알린다 (SKILL.md 3단계).
