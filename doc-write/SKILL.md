# doc-write

자료 전부 열기 → 분석 → **질문 한 번** → 쓰기 → 그림 → 결과물 → 검증 → 보고.

문서가 산출물인 일의 자리다. 다른 skill 은 코드와 노드를 다룬다. 문서에서 되풀이된 교정은 다섯 종류였다.
독자를 안 정하고 씀, 양식·예시를 무시함, 남의 몫을 우리 몫처럼 씀, 못 읽은 자료를 추정으로 채움,
산출물을 덮어쓰거나 잃음. 이 skill 의 순서는 그 다섯을 쓰기 전에 막도록 짰다.

| 참고 | 무엇 |
|------|------|
| [`references/questions.md`](references/questions.md) | 분석 방법(담당 표기, 협업 기관, 최신 분담 근거, 파일명 규칙)과 처음 질문 |
| [`references/writing.md`](references/writing.md) | 쓰기 규칙과 근거 발화 |
| [`references/figures.md`](references/figures.md) | 그림 원칙, 스타일 사양, 출력별 넣는 법, 검사 |
| [`references/hwp.md`](references/hwp.md) | why-hwp 로 hwp/hwpx 를 읽고 고치는 순서와 함정 |
| [`references/formats-submit.md`](references/formats-submit.md) | 제출 양식: 정부과제 보고서·사업계획서·요구사항·제안서·SW 등록 명세서 |
| [`references/formats-present.md`](references/formats-present.md) | 발표·리뷰: 발표 pptx, 발표·리뷰용 md |

| [`references/formats-draft.md`](references/formats-draft.md) | 붙여 넣을 초안: 메일 txt, MR·PR, Jira, Slack |

## 절대 규칙

1. **자료를 전부 열고 쓴다.** 사용자가 준 파일, 가리킨 폴더, "기존에 쓴 것처럼" 의 그 기존 것까지 연다.
   못 연 것이 있으면 **그 자리에서 알리고 멈춘다.** 추정으로 채우지 않는다
   (증상: "모둘별로 뭐할지 계획한 파일들 준것들에 대한 내용은 어따 팔아먹었냐").
2. **분석한 뒤 한 번에 묻고, 답을 받고 쓴다.** 담당, 협업 기관 몫, 독자, 그림, 파일명은 자료마다 다르다.
   질문마다 분석 근거와 추천 답을 붙인다. 묻는 법은 3단계.
3. **우리 몫만 쓴다.** 남의 몫을 우리 쪽으로 끌어오지 않는다. 경계에 걸린 것은 "협의 필요" 로 둔다
   (증상: "왜 자꾸 니는 우리쪽으로 몰을려그래", "이것들은 우리가 고려할 요소가 아니야").
4. **양식·예시가 있으면 그 구성과 스타일을 그대로 따른다.** 형식을 새로 짓지 않는다
   (증상: "예시가 있는데 스타일을 왜 다 무시하고").
5. **최종본으로 쓴다.** 날짜 붙은 결정 경위, 개편 이력, 이전 검토를 넣지 않는다
   (증상: "날짜랑 뭐가 개편됐는지 이런거 지우라고 여기 한문서에서 최종본으로 설명하는거니까").
6. **덮어쓰지 않는다.** 버전을 올려 새 파일로 둔다. git 밖이면 지워지면 못 되살린다고 경로와 함께 알린다
   (증상: 커밋 안 한 리뷰 문서가 사라져 "이거 내용을 다 지워 버렸네").
7. **담당·기관·과제·사람 이름은 자료에서 읽는다.** 이 skill 에는 어느 이름도 적혀 있지 않다.
   예로 든 이름을 그대로 가져다 쓰지 않는다.

## 0. 동시 세션 확인

repo 안 문서를 고칠 때만 본다.

```sh
~/.claude/skills/shared/scripts/session-guard.sh <repo> 10
```

## 1. 자료 전부 열기

**텍스트만 뽑지 말고 모양도 본다.** 양식과 예시는 표 배치, 끝말, 깊이가 곧 따를 규칙이다.

why-hwp 는 설치 때 받아 둔다. 쓸 경로는 이렇게 얻는다.

```sh
WH=$(bash ~/.claude/skills/doc-write/scripts/fetch-why-hwp.sh --which) || echo "why-hwp 없음"
```

없으면 hwp/hwpx 읽기와 변환을 못 한다고 알리고, 다른 자료로 할 수 있는 것만 한다.
받는 법은 `bash ~/.claude/skills/doc-write/scripts/fetch-why-hwp.sh` (폐쇄망은 `WHY_HWP_BIN`).

| 자료 | 여는 법 |
|------|---------|
| `.hwpx`, `.docx` | `"$WH" text <파일>`, `"$WH" info <파일>` |
| `.hwp` | `text`·`info` 가 아직 못 읽는다. 한글이 깔린 Windows 면 `"$WH" convert -to hwpx -o <사본> <파일>` 로 사본을 만들어 읽는다. 아니면 hwpx 나 pdf 로 달라고 한다 (`hwp.md`) |
| 양식 모양 | 한글이 깔린 Windows 면 `"$WH" convert -to pdf` 로 PDF 를 만들어 Read 로 쪽을 본다 |
| `.pdf`, 이미지 | Read (PDF 는 `pages` 로 나눠 읽는다) |
| `.pptx` | zip 이다. `unzip -l` 로 슬라이드 목록, `unzip -p <파일> ppt/slides/slideN.xml` 의 `<a:t>` 가 글자다 |
| md, txt, 코드 | Read |
| "기존에 ~한 것처럼" 의 이전 산출물 | 그 폴더의 이전 파일, repo 의 템플릿, 지난 세션 기록 (`~/.claude/skills/shared/scripts/session-grep.sh`) |

**"N차년도 실적" 같은 말은 맞는 해의 자료를 고른다.** 그해 실적은 그해 하반기(2차) 자료에 있다.
이름이 비슷한 다른 해 자료를 열고 끝내지 않는다.

**못 연 자료는 목록으로 알린다.** 무엇을 못 열었는지, 왜인지, 그것 없이 쓰면 어느 칸이 비는지.
이어서 쓸지는 사용자가 정한다.

## 2. 분석

`references/questions.md` 1절 순서대로 뽑는다. 뽑을 것은 이것이다.

| 무엇 | 왜 |
|------|-----|
| 양식의 절·표·칸 | 무엇을 어디에 쓸지가 여기서 정해진다 |
| 담당 표기와 그 범례 | 우리가 쓸 칸과 남의 칸을 가른다 |
| 협업 기관 | 남의 몫이 어디까지인지 |
| 최신 분담 근거 | 계획서보다 회의록·담당 그림·사용자 말이 최신이다 |
| 파일명·버전 규칙 | 새 파일 이름을 제안한다 |
| 예시의 스타일·깊이·끝말·ID 체계 | 그대로 따른다 |
| 기존 변경 추적·메모 | 보존하고, 이번 수정도 같은 방식으로 남긴다 |
| 올릴 곳·공개 여부 | 공개면 내부 이름을 빼고 검사한다 |

## 3. 질문 한 번 (블로킹)

**분석을 끝낸 뒤 한 번에 묻는다.** 하나 묻고 답 듣고 또 묻지 않는다.
답이 새 질문을 열 때만 다음 라운드가 있다 (`design-first` 3단계와 같은 방식).

| # | 묻는 것 | 추천 답 |
|---|---------|---------|
| 1 | 어느 담당 부분을 쓸지 | 담당 표기 분석에서 우리 표기가 붙은 칸 |
| 2 | 협업 기관 몫을 넣을지 | 넣지 않는다. 경계는 "협의 필요" 로 |
| 3 | 독자 | 자료와 올릴 곳에서 고른 하나. 개발자 / 협업 기관 / 소스를 처음 보는 사람 / 결정권자(기술 요지만) / 제출처 |
| 4 | 올릴 곳·공개 여부 | 자료에서 읽은 것 |
| 5 | 그림 종류 | 발표·외부용은 직접 그린 흐름 그림, 개발자 repo 문서는 그 repo 규약(Mermaid 포함) |
| 6 | 그림 시안 확인 | 시안 한 장을 먼저 확인받을지, 끝까지 그리고 한 번에 볼지 |
| 7 | 파일명 | 폴더에서 뽑은 규칙에 맞춘 이름. "이렇게 진행할까요?" |
| 8 | 이름 표기 | 회사·기관·제품 이름을 그대로 쓸지 기능 이름으로 일반화할지 |
| 9 | 변경 추적 | 남이 만든 양식을 고치면 변경 추적으로 남긴다 |

**사용자가 이미 말한 것은 묻지 않는다.** 그 답을 표에 "말씀하신 대로" 로 적고 넘어간다.
**그 종류에 안 걸리는 질문은 뺀다.** Jira 초안에 그림 질문을 하지 않는다.
분석 근거를 붙여 묻는 형식은 `questions.md` 3절에 예가 있다.

**답을 받으면 첫 줄에 독자와 종류를 한 줄로 알리고 쓴다.**

> "다른 기관 개발자가 읽는 연동 문서로 쓰겠습니다. 코드 위치 없이 동작과 API 위주입니다."

## 4. 쓰기

`references/writing.md` 를 따른다. 종류별 틀은 아래 파일에 있다.

| 종류 | 틀 |
|------|-----|
| 정부과제 보고서, 사업계획서, 요구사항 정의서, 제안서, SW 등록 명세서 | `formats-submit.md` |
| 발표 pptx, 발표·리뷰용 md | `formats-present.md` |
| 외부 README, 설계 문서, 협업 기관 공유 문서, 개발자 repo 문서 | `formats-repo.md` |
| 메일, MR·PR, Jira, Slack | `formats-draft.md` |

**틀보다 사용자가 준 양식·예시가 먼저다.** 틀은 양식이 없을 때 쓴다.

## 5. 그림

`references/figures.md` 를 따른다. 요지만 여기 둔다.

| 무엇 | 어떻게 |
|------|--------|
| 원본 | 항상 SVG. 직접 쓴다. 원본은 산출물 폴더나 repo 에 둔다 (스크래치패드 금지) |
| md | SVG 를 그대로 넣는다. 경로는 문서가 있는 폴더 기준 |
| hwp/hwpx | `"$WH" svg2png -width-mm <들어갈 영역 너비 mm> -o <png> <svg>` (기본 600 dpi) |
| pptx | 템플릿의 네이티브 도형으로 그린다 |
| 확인 | 바꾼 그림은 전부 PNG 로 렌더해 Read 로 직접 본다 |

**시안 확인을 골랐으면 한 장을 내고 멈춘다.** 나머지는 그 한 장의 방향을 받은 뒤 그린다.
끝까지 그리기를 골랐으면 전부 그린 뒤 한 번에 보인다.

## 6. 결과물

| 출력 | 어떻게 |
|------|--------|
| md | 그대로 저장 |
| txt (메일 등) | 마크다운 기호 없이 |
| hwp/hwpx | `references/hwp.md`. 원본은 복사해서 사본을 고친다 |
| pptx | 지정 템플릿 덱을 복사해서 고친다. 처음부터 새로 만들지 않는다 |
| docx | 양식 사본을 고친다. 고치는 도구가 없으면 md 로 쓰고 옮길 위치 표를 같이 낸다 |

**사용자가 말한 형식 그대로 낸다.** "txt" 면 txt, "계단식" 이면 `-` 들여쓰기, "뽑아" 면 파일이다.

## 7. 검증

| 검사 | 어떻게 | 근거 |
|------|--------|------|
| 원본 대비 | hwp/hwpx 는 `text` 를 원본과 고친 본에서 뽑아 diff. 남의 칸·메모·변경 추적 수가 그대로인지 `info` 로 | 남의 몫 보존 |
| 양식 칸 | 체크리스트의 칸이 전부 채워졌거나 "협의 필요"·"원본 확인 필요" 로 표시됐는지 | 양식 따르기 |
| 수치 | 문서의 수치마다 근거 자료의 값과 대조 | 수치는 약속이다 |
| 금지어·내부 이름 | 공개 문서면 내부 이름 목록으로 본문과 그림 원본을 grep. 0건. 그림·캡처 속 글자는 grep 에 안 잡히니 눈으로 | 공개 노출 |
| 그림 | 바꾼 그림을 전부 렌더해 열어 본다. 화살표·겹침·잘림·줄 수 (`figures.md` 9절) | 렌더해서 본다 |
| 경로 | 문서 안 그림·링크가 문서 폴더 기준으로 실제 파일에 닿는지 | 그림 깨짐 |
| 메타 블록 | 제목 바로 아래 대상·작성일·범위 블록이 없는지 | 최종본 |
| em dash | `grep -n $'—' <문서>` 0건 | 전역 규칙 |
| 실행 | "된다" 고 쓴 명령(빠른 시작 등)은 돌려 본다. 못 돌린 것은 못 돌렸다고 쓴다 | 된다고 쓴 것 |
| 같이 고칠 문서 | 같은 내용이 든 언어판, reference 문서, README, 명세서, 발표 자료를 찾아 같이 고쳤는지 | 함께 고칠 것 |

## 8. 보고

**맨 앞에 "보실 문서" 를 경로 하나로 적는다.** 파일이 여럿이면 무엇이 본문인지 적는다
(증상: "그래서 문서는 어떤 문서를 보면 되는데").

| 보고에 넣을 것 | 왜 |
|----------------|-----|
| 산출물의 실제 경로 (그림 원본 포함) | 흩어지면 찾지 못한다 |
| 못 읽은 자료와 그 때문에 빈 칸 | 추정으로 채우지 않았다는 것을 보인다 |
| "추정"·"원본 확인 필요" 로 남긴 칸 | 근거가 약한 곳을 사용자가 고른다 |
| 내가 임의로 적용한 표기 규칙 | 지시받지 않은 규칙은 밝혀 뒤집을 수 있게 한다 |
| 초안 안의 약속 ("다음 릴리즈에 하겠다") | 보낼지와 그 일을 할지 따로 묻는다 |
| 범위 밖에서 본 것 | 고치지 않고 위치와 함께 |
| git 밖 파일 | "지우면 되살릴 수 없다" 와 경로 |

예/아니오로 답할 물음이 있었으면 그 답을 첫 줄에 쓴다.

## 저장 규칙

| 상황 | 어떻게 |
|------|--------|
| 같은 이름 파일이 있음 | 덮어쓰지 않는다. 폴더 규칙대로 버전을 올린다 (`v1.1` → `v1.2`). 사용자가 덮어쓰라고 하면 그때만 |
| 이름을 준 파일 ("mr.md 로 뽑아", "mail.txt") | 그 이름 그대로. repo 안이면 `.claude/` 아래에 두고 커밋하지 않는다. repo 가 `.claude/` 를 추적하면 `.git/info/exclude` 에 넣는다 |
| 열 명령을 안내할 때 | 사용자 편집기 명령이 repo 루트 기준이면 루트 기준 경로로 준다 (`! ge .claude/mr.md`) |
| 사용자에게 낼 산출물 | 스크래치패드에 두지 않는다. 사용자가 말한 폴더, 없으면 자료 폴더나 repo 안 |
| git 밖 | 경로와 함께 "지우면 되살릴 수 없다" 를 알린다 |
| 잠긴 파일 (한글·오피스가 열고 있음) | 알리고 다른 이름으로 저장한다. 남의 프로세스를 끝내지 않는다 |
| 클라우드 동기화 폴더 (OneDrive 등) | 임시 폴더에 저장한 뒤 복사하고 md5 로 같은지 본다 (`hwp.md` 7절) |
| 캡처 | 새 이름으로 찍는다. 성공한 캡처를 덮어쓰지 않는다 |

## 하지 말 것

- 자료를 다 열지 않고 쓰기, 못 연 자료를 추정으로 채우기
- 분석 전에 묻기, 추천 답 없이 묻기, 하나씩 나눠 묻기
- 담당·기관 이름을 이 skill 의 예에서 가져다 쓰기
- 남의 몫을 우리 몫으로 쓰기, 자료끼리 어긋난 것을 한쪽으로 정해 버리기
- 양식·예시가 있는데 새 구성으로 쓰기
- 날짜 붙은 결정 경위, 개편 이력, 맨 위 메타 블록 넣기
- 사용자가 준 KPI 후보·표 양식·배정을 바꾸기
- 발표·외부용 그림을 Mermaid 구조도로 그리기, 한글 ASCII 그림 넣기
- 그림을 렌더해서 보지 않고 넘기기
- 원본 양식을 직접 고치기, 덮어쓰기
- 스크래치패드에 산출물·그림 원본 두기
- 이름 준 문서를 커밋하기 (사용자가 커밋하라고 할 때만)
- 돌려 보지 않은 명령을 "된다" 고 쓰기
