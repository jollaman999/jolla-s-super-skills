# release-cut

태그를 찍고 릴리즈 노트를 쓰고 바이너리를 올린 뒤, **CD 가 만든 이미지를 연동 repo 에 반영하는 데까지** 갑니다.

> "릴리즈 찍어줘", "태그 찍고 릴리즈", "릴리즈 때리고 배포해"

[`deploy-verify`](../deploy-verify/) 와 짝입니다. 이 skill 이 릴리즈를 만들고 저쪽이 노드에 반영합니다.

## 전제

**릴리즈는 되돌리기 어렵습니다.** 태그를 지우고 force push 해야 하고, 그 사이 남이 받아 갔을 수 있습니다.
그래서 태그를 찍기 전에 노트 본문을 통째로 보여주고 승인을 받습니다.

**릴리즈 노트는 공개됩니다.** 커밋 훅은 커밋만 막고 릴리즈 본문은 못 막습니다.
내부 IP·호스트명·사내 제품명·계정을 여기서 걸러냅니다.

**태그만 찍으면 실행 파일은 옛 버전을 말합니다.** 코드에 박힌 버전과 하위 컴포넌트(agent 등)
버전을 먼저 올립니다.

## 흐름

```
동시 세션 확인
  -> 릴리즈 범위 확정 (어느 repo 들, 어느 구간)
  -> 이전 릴리즈 형식 조사      (형식을 새로 만들지 않는다)
  -> 버전이 적힌 곳을 모두 갱신
  -> 변경 목록 수집·분류
  -> 노트 초안 승인             (블로킹)
  -> 커밋·태그·push
  -> 바이너리 빌드·첨부
  -> CD 이미지 대기             (상한 있는 폴링)
  -> 연동 repo 버전 갱신        (보고 후 승인)
  -> deploy-verify 로 넘김
```

## 자주 빠지는 것

| 빠뜨리는 것 | 결과 |
|-------------|------|
| agent 등 하위 컴포넌트 버전 bump | 릴리즈는 됐는데 실행 파일이 옛 버전을 보고 |
| 릴리즈 에셋(바이너리) 첨부 | 받아 쓸 수 있는 산출물이 없음 |
| 연동 repo 의 이미지 태그 갱신 | 배포는 성공하고 노드는 옛 이미지로 뜸 |
| CD 완료 대기 | 아직 없는 이미지를 가리키는 커밋 |

`references/notes.md` 에 노트 구조와 공개 노출 검사 명령이 있습니다.
**기준은 항상 그 repo 의 직전 릴리즈입니다.**
