# D 노드 - 사용자가 말한 것을 그대로 옮기기

**사용자가 준 것이 코드에서 뽑은 것보다 우선한다.** 사용자는 무엇이 맞는 상태인지 알고 있고, 코드는 그렇지 않을 수 있다.

## 1. 기대 상태를 그대로 옮긴다

사용자가 "무엇이 어떻게 보여야 한다"를 말하면 그건 **그대로 판정기준**이다. 재해석하지 않는다.

> "80 포트에서 wordpress, 81포트에서 httpd, 8080에서 바이너리 tomcat, 8081에서 컨테이너 tomcat이 최종 타깃 인프라의 vm에서 보여야 하거든?"

이 한 문장이 항목 4개다:

| id | 대상 | 방법 | 절차 | 판정기준 |
|----|------|------|------|----------|
| VF-01 | 타깃 vm : 80 | ssh | `curl -sS -o /dev/null -w '%{http_code}' localhost:80` + 응답 본문 확인 | wordpress 응답 |
| VF-02 | 타깃 vm : 81 | ssh | 동일, 81 | httpd 응답 |
| VF-03 | 타깃 vm : 8080 | ssh | 동일, 8080 | 바이너리 tomcat 응답 |
| VF-04 | 타깃 vm : 8081 | ssh | 동일, 8081 | 컨테이너 tomcat 응답 |

규칙:
- **사용자가 쓴 표현을 판정기준에 그대로 남긴다.** "wordpress 가 보여야 함" 을 "200 응답" 으로 바꾸지 않는다. 200 이 떠도 wordpress 가 아닐 수 있다.
- 사용자가 "이건 아니어야 해" 라고 한 것도 항목이다 (부정 조건).
- 사용자 기준과 코드에서 뽑은 기준이 **충돌하면 E 에서 짚어 묻는다.** 임의로 한쪽을 고르지 않는다.

## 2. curl 붙여넣기 파싱

브라우저 DevTools 의 `copy as cURL` 을 그대로 던지는 경우가 있다. 여기엔 엔드포인트·헤더·인증이 전부 들어 있다.

추출할 것:

| 항목 | 어디서 |
|------|--------|
| 메서드 | `-X` 또는 `--data` 있으면 POST |
| URL | 첫 인자. 호스트·포트·경로 |
| 인증 | `-H 'authorization: Bearer ...'` 또는 `-b 'Authorization=...'` (쿠키) |
| 본문 | `--data-raw`, `-d` |
| 콘텐츠 타입 | `-H 'content-type: ...'` |

**JWT 만료를 먼저 확인한다.** 만료된 토큰으로 검증하면 401 이 나오고 그걸 기능 실패로 오독한다.

```sh
# payload 의 exp 를 사람이 읽는 시각으로
echo "$JWT" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null | python3 -c \
  'import sys,json,datetime; d=json.load(sys.stdin); print("exp:", datetime.datetime.fromtimestamp(d["exp"]))'
```

만료됐으면 **검증을 시작하기 전에** 새 토큰을 요청한다. 이미 만료된 것을 알고도 실행하지 않는다.

정리 규칙:
- 붙여넣은 curl 은 **그대로 실행하지 않는다.** `-H` 를 다 옮기지 말고 인증·콘텐츠타입만 남긴다. `sec-ch-ua`, `referer` 같은 브라우저 헤더는 뺀다.
- 토큰은 변수로 뽑는다. 명령 원문에 그대로 적지 않는다.
- 이 curl 이 **상태를 바꾸는지** 판정한다. `create`, `delete`, `update` 가 경로나 메서드에 있으면 민감도 `위험`.

## 3. 에러 로그 붙여넣기 파싱

로그·스택트레이스를 던지는 경우는 검증 요청이 아니라 **원인 추적 요청**인 경우가 많다.

판별:
- 로그에 이미 실패가 찍혀 있고 사용자가 "왜 이래?" 를 묻는다 → **F 를 건너뛰고 H 로 바로 간다.** 이미 재현된 실패를 다시 재현할 이유가 없다.
- 로그가 정상인데 "이게 맞아?" 를 묻는다 → 확인 요청. light 경로.

추출할 것:

| 항목 | 쓰임 |
|------|------|
| 예외 타입·메시지 | 검색어. `grep` 으로 코드에서 발생 지점을 찾는다 |
| 스택의 최상단 자기 코드 프레임 | 라이브러리 프레임을 건너뛰고 우리 코드가 처음 나오는 줄 → `file:line` |
| 타임스탬프 | 로그 조회 범위 (`--since`) 를 여기 맞춘다 |
| 요청 경로·메서드 | 어느 진입점인지 |
| 상태 코드 | 400 대는 입력/계약 문제, 500 대는 내부 |

로그에 토큰·비밀번호가 섞여 있으면 **인용할 때 마스킹**한다. 사용자가 준 것이라도 보고서에 평문으로 남기지 않는다.
