# 경계 조건 - pass 다음에 반드시 오는 질문

## 왜 필요한가

동작하는 결과가 나오면 **곧바로 "그러면 이럴 때는?" 이 온다.** 관측된 흐름:

| 순서 | 질문 |
|------|------|
| 1 | (스크립트 정상 출력 확인) |
| 2 | "그러면 호스트에서의 전체 GPU 모니터링은 어떻게 수집해야 하지? **호스트에 nvidia 드라이버가 없다면?**" |
| 3 | "그러면 **호스트에 GPU 5개** 있어 이럴 때는 각각 VM 매핑 구조를 찾아서..." |
| 4 | "gpu_type이 패스스루이면서 **hypervisor 태그가 그 호스트에 해당되는** 걸로 뽑아내야겠네?" |

성공에서 멈추지 않고 **운영 환경에서 깨질 조건**을 먼저 찾는다.
그러니 G 에서 pass 를 보고할 때 이 질문을 **먼저 던져 놓는다.** 사용자가 묻고 나서 찾으면 한 바퀴 늦다.

## 어떻게 뽑나

pass 한 항목마다 아래를 대입한다. 해당하지 않는 것은 건너뛴다.

| 축 | 질문 | 예 |
|----|------|-----|
| **0 / 없음** | 대상이 아예 없으면? | 드라이버 미설치, GPU 0장, 데이터 0건, 목록 빈 배열 |
| **N 개** | 1개가 아니라 여러 개면? | GPU 5장, 노드 100개, 페이지 넘는 목록 |
| **빈 값** | 필드가 비면? | 빈 태그로 InfluxDB 파싱 에러 -> `"N/A"` 기본값 필요 |
| **권한** | 권한 없는 주체가 부르면? | 저권한 토큰, 토큰 없음, 만료 토큰 |
| **타이밍** | 순서가 뒤바뀌면? | 재기동 직후, 수집 전, 동시 요청 |
| **환경 차이** | 다른 사이트에서도 같나? | 사이트별 설정·버전·데이터 차이 |
| **규모** | 운영 데이터 규모에서도? | 로컬 10건 vs 운영 100만건 |
| **의존 장애** | 붙는 대상이 죽으면? | DB·외부 API·큐 다운 시 동작 |

## 데이터 파이프라인은 끝까지 본다

수집 -> 변환 -> 저장 -> 조회 중 **한 곳만 보고 pass 하지 않는다.**
실제 사례: GPU 매핑 스크립트가 빈 태그 값(`instance=`)을 내보내 **InfluxDB 쪽에서** 파싱 에러가 났다.
스크립트만 보면 정상이다. 저장 단계까지 따라가야 보인다.

## G 에서의 형식

pass 표 아래에 붙인다. 길게 쓰지 않는다.

```
## 확인 안 된 경계 조건
| 항목 | 조건 | 왜 깨질 수 있나 | 확인 방법 |
|------|------|-----------------|-----------|
| VF-01 | GPU 0장인 호스트 | nvidia-smi 부재 시 분기 미확인 | 드라이버 없는 노드에서 재실행 |
| VF-02 | 수집 데이터 0건 | 빈 태그로 저장 단계에서 깨질 수 있음 | 신규 노드에서 첫 수집 관찰 |
```

**추측으로 "괜찮을 것" 이라고 쓰지 않는다.** 확인 안 했으면 확인 안 했다고 적는다.
확인할 수 있는 것이면 E 에서 승인받아 항목으로 만든다.
