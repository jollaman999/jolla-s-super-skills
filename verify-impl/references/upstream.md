# upstream 경로 - 외부 새 버전·보안 공지 대조

"커널 업데이트 있나", "이 CVE 조치됐나", "airflow 3.3.2 로 올릴 거 있나" 처럼 **바깥에서 바뀐 것이 우리에게 걸리는지** 묻는 요청이다.
노드에 붙지 않고 외부 조회와 git 대조로 답이 나온다. 팀원·체크리스트·승인 없이 팀장이 아래 점검표대로 직접 한다.

## 왜 점검표인가

2026-10~11 세션 기록 7건을 읽었다. 절차가 무거워 헛돈 곳은 없었고, **확인 범위가 빠져서** 사용자가 다시 물었다.

| 빠진 것 | 들은 말 |
|---------|---------|
| 배포판 태그만 보고 원본(kernel.org) stable 을 안 봄 | "그러면 7.3.x 패치 적용하는건?" |
| 보안 공지 하나만 대조함 | "그래서 할게 없다는거야?" |
| 반영안에서 repo 의 버전 표기 관례를 안 봄 | "Makefile 은 왜 7.3.0 이야" |

## 점검표

| # | 할 일 | 어떻게 | 빠뜨리면 |
|---|-------|--------|----------|
| 1 | 지금 기준을 확정한다 | `git describe --tags`, 버전 파일(Makefile `VERSION`·`PATCHLEVEL`·`SUBLEVEL`, `debian*/changelog` 첫 줄, `pyproject`·`requirements`·`go.mod`), 바이너리면 그 안의 `release` 파일 | 무엇과 비교했는지 모르는 답이 된다 |
| 2 | 업스트림 최신을 **출처마다** 본다 | 배포판이 있으면 배포판과 원본을 둘 다. 예: Ubuntu 태그 **와** kernel.org stable. PyPI JSON, GitHub release, 컨테이너 레지스트리 태그 | 한쪽 출처의 패치를 통째로 놓친다 |
| 3 | 차이를 계산한다 | `git ls-remote --tags`, `git cherry -v`, `git merge-base --is-ancestor`, `git tag --contains`. 원격 브랜치가 필요하면 그 ref 만 전체로 받는다 | 이미 들어간 것을 새것으로 보고한다 |
| 4 | 보안 공지는 **기간 안의 것 전체**를 대조한다 | 배포판 보안 페이지(ubuntu.com/security/notices 등)·벤더 advisory 의 최근 목록을 훑고, 각 공지의 수정 커밋·수정 버전이 우리 소스에 들어 있는지 본다. 사용자가 하나를 지목했어도 그 하나로 끝내지 않는다. 대조하지 못한 공지는 "대조 못 함" 으로 이름을 적는다 | "할 게 없다" 가 공지 하나만 본 결론이 된다 |
| 5 | 반영안을 낼 때 repo 의 버전 표기를 같이 낸다 | 최근 버전 올림 커밋(`git log -p -- Makefile debian*/changelog`)에서 관례를 읽어 "반영하면 버전은 이렇게 된다" 예시를 붙인다 | 반영 단계에서 버전 표기를 다시 고친다 |

**`git fetch --depth` 를 쓰지 않는다.** 이미 전체 기록이 있는 repo 를 shallow 로 바꿔 버린다(2da48abc, 되돌리는 데 `--unshallow` 가 들었다).
최신 태그만 알면 되면 `git ls-remote` 로 끝낸다.

**실제 배포된 것을 봐야 갈리면 그 항목만 `light` 로 올린다.** 노드에 깔린 커널·이미지·바이너리 버전은 B′ 실접속 승인을 받고 본다.
소스에 들어 있다는 것과 돌고 있는 바이너리에 들어 있다는 것은 다른 주장이다.

## 보고

```
| 대상 | 지금 | 최신 (배포판) | 최신 (원본) | 우리에게 없는 것 | 근거 |
|------|------|---------------|-------------|------------------|------|
| 커널 | 7.3.0-21.21 (Ubuntu-7.3.0-11.12 + v7.3.3) | Ubuntu-7.3.0-12.13 | v7.3.5 | v7.3.4·v7.3.5, apparmor 수정 1건 | git ls-remote, git cherry -v |

| 보안 공지 | 조치 | 근거 |
|-----------|------|------|
| USN-0000-1 | 됨 | 수정 커밋 abc1234 가 HEAD 에 있음 (merge-base) |
| USN-0000-2 | 대조 못 함 | 수정 커밋을 공지에서 못 찾음 |
```

반영(cherry-pick·버전 올림·빌드·설치)은 하지 않는다. 요청에 있으면 확인 결과를 내고 `release-cut`·`deploy-verify` 로 넘긴다.
