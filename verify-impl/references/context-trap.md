# 검증 컨텍스트 함정

무음 실패(`silent-failure.md`)가 "값이 조용히 틀린" 것이라면, 여기 있는 건 **"내가 본 것이 검증 대상이 아니었던"** 경우다.

## 1. 실행 주체가 다르면 결과가 다르다

**내가 손으로 돌린 결과는 실제 운영에서 도는 결과가 아니다.**

> 노드에서 `gpu_vm_mapping.sh` 를 일반 유저로 직접 돌리면 rootless podman 이 `nova_libvirt` 를 못 봐
> `status=unassigned` 가 나온다. **에이전트는 root 라 정상**(`status=assigned`).
> 수동 실행 결과로 "매핑 안 됨" 이라 판단하지 말 것.

검증 전에 맞춰야 할 것:

| 축 | 확인 |
|----|------|
| 사용자·권한 | 운영은 root 인가 서비스 계정인가. 나는 무엇으로 붙었나 |
| 컨테이너 컨텍스트 | 호스트에서 보는 것과 컨테이너 안에서 보는 것이 다르다 (rootless podman, 네임스페이스) |
| 환경변수 | 서비스 유닛의 `Environment=`, compose 의 `environment:` 가 셸에는 없다 |
| 작업 디렉터리 | 상대경로가 다르게 풀린다 |
| PATH | 서비스가 쓰는 바이너리와 셸이 찾는 바이너리가 다를 수 있다 |

맞출 수 없으면 **맞출 수 없다는 사실을 evidence 에 적고**, 저장소·로그 같은 **제3의 경로로 교차 확인**한다.
예: 스크립트를 손으로 돌려보는 대신 그 스크립트가 실제로 쓴 값을 InfluxDB 에서 읽는다.

## 2. 동명이인

같은 이름의 것이 둘 있으면 엉뚱한 걸 보고 판정하게 된다.

> 실제 에이전트는 `cmp-telegraf-demo.service`(`/cmp-agent/sites/<site>/telegraf/bin/cmp-telegraf`) 다.
> OS 기본 `telegraf.service` 도 (masked 상태로) 떠 있으니 헷갈리지 말 것.

> 실배포 서버의 **SSH 는 포트 22 다. 10022 가 아니다.**

확인할 것:
- 서비스명·유닛명이 여러 개 있는가. 어느 것이 진짜 대상인가
- 실행 중인 바이너리의 **실제 경로**를 확인했는가 (`systemctl show -p ExecStart`, `readlink /proc/<pid>/exe`)
- 포트가 통념과 같은가. 사이트마다 다를 수 있다
- 설정 파일이 여러 곳에 있는가. 실제로 읽히는 건 어느 것인가

## 3. fail 로 보이지만 정상인 것

**데이터 0건이 설계상 정상인 경우가 있다.** 원인을 찾기 전에 이것부터 배제한다.

> passthrough 노드는 GPU 가 vfio-pci 에 바인딩돼 호스트에 NVIDIA 드라이버가 아예 없다.
> 그래서 호스트는 GPU 텔레메트리를 물리적으로 못 읽는다. **`type=host` 0건 자체는 버그가 아니다.**

> `SHOW FIELD KEYS` 에 `pstate` 가 float+integer 둘 다 보이는 건 **옛 샤드 잔재로 무해**하다.

H(원인 추적) 진입 전에 확인:
- 이 구성에서 그 데이터가 **원래 생기는 게 맞나**
- 다른 경로로 대체 수집되고 있지는 않나 (passthrough 는 게스트 시리즈를 물리 GPU 로 매핑)
- 옛 스키마·옛 샤드의 잔재인가
- **선재 실패**인가 (검증 전부터 깨져 있었나)

정상인데 원인을 파면 시간만 버린다. 반대로 정상이라고 넘겼는데 아니면 놓친다. **판단 근거를 evidence 에 적는다.**

## 4. 간헐 실패는 재시도로 가른다

> Tumblebug API 는 가끔 `401 Unauthorized` 가 뜬다 - transient 다. 재시도하면 된다.

- 실패가 나오면 **같은 명령을 2회까지 재시도**한다. 간격을 둔다.
- 3회 모두 같은 실패면 `fail`. 섞이면 `unknown` + "간헐적" 으로 올리고 재현율을 적는다 (3회 중 1회 등).
- **간헐 실패를 기능 실패로 단정하지 않는다.** 반대로 한 번 통과했다고 pass 로 올리지도 않는다.
- 재시도해도 되는 것은 **읽기뿐이다.** 상태를 바꾸는 호출은 재시도하지 않는다 (중복 생성).
