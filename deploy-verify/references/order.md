# 순서 - 틀리면 되돌릴 수 없는 조합

각 단계는 안전해도 **순서가 틀리면 사고가 난다.**

> "재설치를 먼저하고 데이터날리고 가동했어야지"

| 조합 | 올바른 순서 | 틀리면 |
|------|-------------|--------|
| 재설치 + 데이터 초기화 | 재설치 → 초기화 → 기동 | 새 스키마에 옛 데이터가 남아 깨짐 |
| 배포 + 검증 | 배포 → **반영 확인** → 검증 | 옛 바이너리를 검증하고 pass |
| 설정 변경 + 재기동 | **백업** → 변경 → 재기동 → 확인 | 원복 불가 |
| 빌드 + 커밋 | 빌드 성공 → 커밋 | 안 되는 코드를 커밋 |
| 마이그레이션 + 원본 정리 | 마이그레이션 → **검증** → 원본 정리 | 실패했는데 원본이 없음 |
| 다중 호스트 | 한 대 → 확인 → 다음 대 | 전부 같이 깨짐 |
| 스키마 변경 + 앱 배포 | 하위호환 스키마 → 앱 → 정리 | 배포 중 앱이 옛 스키마를 못 읽음 |

## 확인 순서

배포 계획을 세울 때 이 질문을 순서대로 한다.

1. 이 중 **되돌릴 수 없는 것**이 있나? 있으면 그게 마지막에 오도록 재배치한다.
2. **백업이 필요한 것**이 있나? 백업이 첫 단계다.
3. **검증이 선행돼야 하는 정리 작업**이 있나? 정리는 항상 검증 뒤다.
4. 여러 호스트면 **한 대씩인가 동시인가?** 운영이면 한 대씩이 기본이다.

순서가 확정되면 **사용자에게 순서 그대로 보여주고 승인받는다.** 순서를 바꿔야 한다면 그때 말이 나온다.
